# 企业研究可靠性 · 2026-10-05

本轮在独立工作区修改查询复用、浏览器快照和状态读取。沿用主线账号、原件、金融规则和界面；不修改生产数据，不调用外部金融接口或模型。

## 已复现问题与修复

1. **研究模式被忽略。** 原共享匹配仅比较代码、机构、年度和用途，可能把旧原件研究复用为新的快速财务研究。回归用例在修改前实际失败。现由 `shared/company-run-reuse.ts` 统一前端、服务端和浏览器缓存；新建页明确传 `financial`，历史无模式记录按 `deep` 兼容。不同模式分别保存，不改旧记录。
2. **一次状态读取失败就停止更新。** 企业页和共享记录列表改用 `src/research-status-poller.ts`。单次 GET 15 秒期限，临时网络错误、超时及 HTTP 408/500/502/503/504 最多重试三次，间隔 1.5、3、6 秒。仍失败则保留错误与手动重试，不无限轮询。401/404/429、取消、解析和程序错误不自动重试。超时文案仅用于研究状态，其他 API 错误保持原含义。
3. **后台仍在读取。** 页面隐藏或离线时清除待执行读取，已经发出的请求可以完成；回到前台或联网后读取一次保存状态，任务未完成才继续。连续唤醒合并，组件退出取消订阅与当前请求。只有实际状态/版本变化才通知记录列表，避免每次读取重复通知。
4. **迟到快照可覆盖新缓存。** 已知资料 revision 优先，其次在缺少版本时使用实际取得日期；同一资料下再比较分析 revision，拒绝同版本已完成结果退回 loading。更高版本允许进入新一轮 loading。没有修改取得日期、模型结果或金额。

这组自动重试只恢复保存状态读取。失败的资料获取、模型分析、上传和取消写操作仍需明确操作；没有新增自动检索或模型重试。已有取消持久化、后台任务 revision 校验与重启恢复机制保持。

## 验证入口

- `tests/company-run-reuse.test.ts`：模式边界、历史兼容与已有范围匹配。
- `tests/company-run-cache.test.ts`：账号、删除与跨页缓存，旧资料/旧分析/完成后迟到 loading 拒绝，更高版本接收。
- `tests/company-financial-default-api.test.ts`：真实隔离 API 中 deep 与 financial 创建不同记录，正确模式重复请求不增加工具调用，历史无模式复用；并保留取消、刷新失败和重启恢复检查。
- `tests/research-status-poller.test.ts`：有限退避、暂停/恢复、并发合并、终止、错误分类与未启动请求取消。使用可控时钟，不依赖外部服务。
- `scripts/browser-qa.mjs`：真实应用、临时账号与明确标记的合成财务 GET 快照。阻塞首次状态请求时缓存先渲染；503 后自动恢复；模拟 document 隐藏状态暂停两种读取；浏览器离线后联网读取完成并停止；期间研究写请求为零。隐藏状态由事件模拟，不冒充真实操作系统切换标签的验收。

实际结果：`npm run check` 通过，1106 项测试全部通过，无失败或取消；类型、构建、格式和竞品记录检查通过。固定版本仓库规范检查通过。

完整浏览器验收 30 项通过、8 张截图，无页面异常；覆盖桌面、390px、账号隔离、七项导航、来源/报告和助手。账号恢复浏览器验收另有 6 项通过、2 张截图。浏览器回执及截图位于忽略提交的 `output/browser-qa/`，账号恢复结果位于其 `reliability/` 子目录。合成来源与 GET 叠加的测试不代表真实 AI 运行。

## 验证边界

本机验证不等于生产上线、真实来源可用或模型质量验收。自动部署由既有主线流程运行，本轮不等待 CI/部署、不 SSH。生产邮件、真实备份隔离验收和九项历史缺失调查仍见[上一阶段记录](reliability-foundation-2026-10-05.md)，没有在此恢复或改写。
