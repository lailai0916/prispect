# 析光 Prispect：产品、研究与实施方案

## 当前方案（2026-10-02）

本节取代下方早期方案的产品主线。历史财表核验继续作为证据工具，不再要求所有用户先生成一份公司报告。

产品围绕一项具体付款决定：**这笔款项目前有哪些依据，哪个条件仍缺材料，换一种付款安排会改变什么？** 两种任务共享来源和确定性计算，但输入与可控制动作不同。

| 视角       | 具体任务                                   | 所需材料                                                           | 可计算结果与下一步                                                                                     |
| ---------- | ------------------------------------------ | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| 外部普通人 | 帮家人核对一笔预付款；比较全额与条件首付   | 签约、收款与退款责任主体，付款与交付条款，已付/已交付/实际退款记录 | 本人未交付资金敞口，与自己设定的上限比较；指出仍需核对的主体或付款条件，不预测对方账本                 |
| 内部接手者 | 是否形成一项新增付款承诺；比较不同付款日期 | 当前可用余额、明确日期的收付款、刚性与可协商属性，关键回款依据     | 90日事件现金路径、首个事件日末低于底线、同日先付款保守余额与条件支付上限；注明未来回款条件与待协商权限 |

新增机制只做三项：

1. **有版本的决定卡。** 保存主体、金额、日期、允许改变的变量、用户自设约束与材料。每次修改、加入/撤回/恢复证据形成新版本；恢复旧版仍是新评估。服务端检查账号与 `baseRevision`，拒绝过期写入。适用范围更正只改变主体和日期，保留原文、金额与来源；历史版本和冲突记录仍可读，恢复旧范围会重新评估并重开相应冲突。
2. **补件与依赖检验。** 记录材料范围、原文字段、主体、日期与出处；区分来源记录、对方陈述、用户假设。同一范围和证据槽出现不同来源金额时保留冲突，不静默覆盖。来源文本定位是有限的主体、日期、金额、收付方向等字段检查，不证明鉴真、完整语义、法律效力或未来履行。未绑定原件的转录不作为来源依据参与记录计算；撤回依据只使依赖它的记录计算未知，明确录入的假设测算仍单独展示。历史年报为可选背景，不作为当前付款任务必须先补齐的材料。生成补件卡或勾选跟进不表示已经联系企业或核实事实。
3. **两个方案的确定性测算。** 外部比较自己的付款敞口，不要求普通人伪造企业90日计划；内部按具体日期计算，揭示月末余额掩盖的早期缺口。同日收支顺序未知时显示期末与先付款保守分支，不认证日内可支付。未知不填0；金额使用整数分避免程序增加误差，但原表千元披露不因此变为分级精度。

公开企业Agent继续真实获取巨潮A股主体、中文指定年报、PDF/哈希、相关合并财表，并在实际页白名单内选择复核。候选需人工确认；近期公告标题仅为线索。私有决定和人工计划只由服务器规则处理，不发外部模型。未授权的商业接口不接入，不写成已取得工商/司法/履约数据。

财报的作用是提出待核问题。集团年报不替代合同主体责任；年度经营现金不替代今天可用现金；CFO/合并净利润不等于销售回款率。负向营运资本调整可提出扩张备货/结算变化或回款/去化压力等竞争解释，可能并存且不穷尽；不能单凭现金桥裁定原因。经营、投资、筹资与期末现金分别列报，购建长期资产通常在投资活动，不能把“建厂”直接当作经营现金低的充分原因。[财政部财务报表格式](https://kjs.mof.gov.cn/zhengcefabu/201905/P020190510359607790104.pdf)

创新主张限于可现场证明的约束：撤回一项依据，相关判断撤回，无关事实保留；补入不同范围的材料不被采用；补入相关字段才恢复局部门槛；两个方案因日期不同出现不同现金路径。天眼查已声明财务/尽调/Agent与合同建议能力，不能把搜索、白话、引用或有下一步本身说成独有。没有真人访谈、付费或市场规模验证；商业价值以具体用户任务与可试用工作流为假设。

验收任务明确标为虚构：外部10万元全付与2万元首付、自设2万元敞口上限；内部12万元起点、D10/40/70各付10万，D25收20万、D55/85各收12万，6万元采购D5与D26。两内部方案期末同16/18/20万；原方案D10缺4万，对照最低2万。真实公开年报与这些人工计划不混成公司预测。

三个独立Pro咨询已完成，产品/严格评委/Agent审计提出上述决定主线和反例。它们是设计参考，不是正式题面或实现验收。最终完成以实际代码、测试、浏览器、公网同版本为准。

### 当前流程、数据与验证范围

两条决定流均可从首页直接开始：录入具体交易或日期计划 → 保存决定版本 → 绑定本账号材料中的原文 → 查看局部条件、补件与假设/有记录测算 → 加入、撤回、恢复或更正证据范围 → 重开历史版本并重新评估。无需先取得上市公司年报。外部交易区分合同、收款、退款责任主体；实际退款与承诺退款分开，金额还须满足整笔交易范围。内部以测算基准日为 D0、次日为 D1，按已列 D0–90 事件计算；首次日末低于自设底线不等于已证明破产，同日次序敏感也不能被正的日末余额掩盖。

财报工具保留完整链路：巨潮大陆 A 股披露主体确认 → LangGraph 并行获取指定年度中文完整年报、相关附注与选定的近期公告原件 → 按实际财务信号有限补查 → 规则核对表格候选 → 人工核对单位、年度、合并范围后采用 → 财报核查、原件、跟进、对比和 HTML/JSON 输出。近期公告只读取有限的选定全文，不代表完整风险调查。无匹配、接口受限、无年报或不可解析时保留实际停止原因；不换成样本公司冒充查询结果。

已核验样本为松原安全、海康威视；宁德时代是额外真实的通用提取案例。宁德 2025 年报合并现金补充表跨 PDF 第 200–201 页，原表单位为人民币千元。提取将显式千元金额换算为元并保留原文单位；整数分计算不会提高原始披露精度。其 2025 原始调整行与净利润的求和比列报 CFO 少 2,000 元，差异保留，完整现金桥和依赖解释停止；不添加残差凑平，也不由差异推断造假。2024 比较列能核对。这些案例不证明任意 A 股、任意年度或扫描 PDF 都能正确提取；金融企业等不适用同一工业企业现金桥时需停止或另行确认。

财报任务原有三段 30/60/90 天假设工作表及回款比例、延后 30 天、额外付款压力测试继续保留。它只显示区间期末结果，不能推出月内首次缺口。付款决定中的具体日期事件计划另算日末路径、先付款保守分支和逆向条件。两者均不从年报填当前余额或未来回款，缺失不补零，条件阈值不是支付授权。

当前代码与已发布基线已包含决定、公开 Agent、账号、主题、双语专业页面及日期规则反例。完整 SHA 为 `2c48ba956faa60bf93b687bb75e86ec66815a4d8`，CI／自动部署／服务器及匿名全部公开资产已核对，详见 [acceptance.md](acceptance.md)。本轮额外修复的解释材料和核查动作仍需自己的完整检查、UI 操作与发布验收；历史基础设施版本不能代替。

### 当前模型发送范围

财报默认规则模式不调用模型，复制或压力测试新财报任务默认关闭模型。公开企业查询初始启用已配置模型，开始前说明外发范围并可关闭，独立于财报解释选项。TokenFlux 是第三方兼容接口；返回的 `gpt-6.1-sol` 标识不代表本项目验证了上游型号或 OpenAI 官方直连。Fast 遵从用户已设置的提供方平台配置；不额外发送 priority，也不作未经实测的速度保证。

- 财报解释发送本次可采用观测的 `id/key/year/value/unit/currency/scope/quote`，以及 `verdict` 和非管理层说法的 `deterministicFindings`（`id/label/explanation/basis`）。不发送被撤回、冲突或未采用的观测；规则分析字段也属于发送内容，不能只披露为金额与摘录。公司名、来源 URL 和原件全文不是这个解释请求的单独字段。
- 公开 Agent 的页规划发送公开 `identity`（代码、名称）、`reportTitle`、`requestedYear`、候选白名单（页或公告 ID、标题、短摘录）、规则信号及 `actionBudget`。模型只能选实际提供的页、公告和动作；服务端在所选范围作确定性提取与比较。竞争解释只能引用已取得的公开片段；后续财务解释沿用上项字段，冲突时跳过解释，不让模型改来源金额。
- 私有付款决定的输入、交易记录、材料原文、备注和日期现金计划不走外部模型；由服务端规则处理。用户授权解释某次财报观测不等于授权发送私有决定材料。

财报解释默认单次超时 60 秒、配置上限 90 秒。公开 Agent 每个逻辑运行最多预留32次来源和12次模型尝试，恢复累计不归零；每次执行窗口480秒，恢复获得新窗口。单进程最多2个查询，来源与模型分别最多2和3个在途操作。财务分支仍有局部调用和响应限制。失败查询24小时内可按原主体、年度和配置恢复，成功前的最终保存失败也可继续补发布。历史调用耗时只说明对应当次，不承诺现场网络速度；测试网络替代不证明供应商实网成功。引用、金额及格式检查都不能认证完整语义。

### 1. 定位与决策（早期记录）

一句话定位：为采购与经营负责人核查一家上市合作方的“利润是否兑现为经营现金”，把一条经营说法变成可重算、可追溯、可继续询证的核查底稿。

具体任务：在长周期采购合作前，使用双方已能取得的年度合并材料，核查利润增长与经营现金之间的差距，并形成针对票据结算、应收回款、备货依据的材料请求。只支撑合作前财务线索核查，不决定投资、授信或公司可靠性，不预测违约概率。

目标用户与付费意愿属于待验证假设。专业机构原始披露证明现金配比、账龄及期后回款属于实际尽调方法；没有本队真人访谈。业务价值先通过可复现核查任务证明，不宣称节省比例、客户认可或市场验证。

三候选已比较：现金兑现核查、客户集中与应收核查、宣传说法交叉核查。选择第一项，因为已取得两份真实年报、数值可独立重算、核心信息可在 30 秒内呈现；第二项受客户匿名限制；第三项的语义裁定范围宽且容易变成通用问答。详见研究文档。

### 2. 防止同质化（早期记录）

已有商业产品覆盖企业评分、多源画像、舆情与投研 Agent，不能宣称本项目首先实现了这些能力。现金桥也是已有会计方法，不能把方法本身当发明。

本次的产品取舍是“核查一条说法”，而非任意公司搜索或综合评分。核心体验把三件事连接：同口径现金桥、原件定位与双向解释、证据压力测试。评委可以亲手移除附注或切换母公司口径，系统实际重新分析，停止没有材料支持的结论，并生成明确的补件问题。这是可展示的产品差异，不是对所有竞品的能力否定或首创声明。

同一组占款数字保留两种可能解释：扩张与结算结构变化，或回款/去化压力。管理层解释只标为公司说法，公开财报不能独立裁定是否坏账。报告列出目前材料能证明的事实、不能证明的因果和下一步需提供什么。解释质量优先于刺激性的风险标签。

### 4. 用户旅程和网站职责（早期记录）

1. 入口：首页提出可检验的问题，用已核验样本的真实数据对比进入核心案例；清楚标注公开报告与历史期间。
2. 工作台：显示真实任务、状态与材料覆盖；新建、重新打开、复制、比较已有任务。
3. 新建核查：选官方样本，或导入支持的结构化材料；确认公司、期间、单位、合并口径与核查目标。
4. 材料中心：列表、筛选、来源/日期/哈希/页码、删除未被任务使用的材料；原件读取及导入结果。
5. 任务执行：展示真实阶段事件，不用假进度动画；失败可重试，有实际错误说明。
6. 报告：结论、两年指标、净利润到 CFO 的现金桥、证据完整性、支持/不足/冲突检查、不同解释及后续问题。每个图形数据来自处理结果。
7. 证据核查：抽屉/页面展示短摘录、来源、页码、主体、单位与期间；本机原件定位和公开原件链接。
8. 压力测试：明确“改变本次提供的材料，重新核查”，不会声称原公司没有披露；保留原任务并另建任务，差异可比较。
9. 历史复用：刷新不丢任务；复制可替换材料；问题完成状态保存。
10. 输出：可实际下载的报告 HTML/JSON，适合打印的版式；必要时服务端 PDF 导出，输出必须用真实报告数据。
11. 方法与演示：公式、支持边界、规则/模型分别承担的任务、两种解释及局限；显式确认后重置演示工作区。中英文界面同等核心流程。
12. 账号：公开首页与示例，真实注册/登录后进入私人工作区；刷新恢复会话，账号设置可改姓名和密码、退出；账号 A 无法读取或操作账号 B 的材料、任务与导出。重置只影响当前账号。

页面共享服务端任务与材料，不堆积空页面。只有有效操作才展示为可用。

### 5. 数据和方法（早期记录）

范围：两家公开上市公司的 2025 年年度合并现金流补充表及其 2024 比较列。真实案例松原安全与海康威视；第三例人为仅提供选定材料。财报非实时状态，行业不同，不作健康排名。

原件、SHA256、发布日期、PDF/印刷页码已核验。原始 PDF 保留本机并忽略 Git；提交来源元数据、必要短摘录与事实字段，提供哈希校验下载脚本。报告原文不改授 MIT/CC 许可。商用再分发须另核权限。

输入支持 JSON/CSV 规范与文本型 PDF 提取。PDF 自动提取须校验表名、列顺序、期间、单位与合并范围；无法确认时返回预览或信息不足，不猜值。扫描件/OCR、任意企业覆盖和私有工商数据库不是承诺能力。结构化导入和界面编辑必须接受新数据而非只认样本文件名。

货币值以十进制字符串记录，按币种和单位转为整数分计算。缺失为缺失，不填零。净利润和经营现金均必须来自合并年度口径；混用母公司、不同期间、不同币种或无法确认单位时停止相关计算。

现金桥：合并净利润 + 存货调整 + 经营性应收调整 + 经营性应付调整 + 其余已披露调整分组 = CFO。完整附注存在时其余分组另对原表求和；只有头部指标时可显示差额，但不能把差额当成已经解释的来源事实。应收现金桥调整不等于单一应收账款余额变化，存货调整也不直接等于滞销。

现金转化比例 = CFO / 合并净利润，净利润 <= 0 时不产生通常比例解读；同比基数为零或负值时不显示常规增长率，改呈现金额变化。任何阈值只用于排查顺序，不代表信用等级，不产生任意总分。

重要判断区分原文事实、派生计算、管理层说法、产品规则与待验证假设。输入存在冲突时展示双方证据并拒绝静默覆盖。所有结论保存输入快照，历史任务不因后续材料删除而变。

### 6. AI 与确定性逻辑（早期记录）

方案启动时本项目没有可用模型 API 凭据；随后用户提供并授权使用 TokenFlux 第三方 OpenAI 兼容接口，已用公开年报数据完成真实调用。服务声明的模型 ID 为 `gpt-6.1-sol`，本项目没有独立验证其上游身份。凭据只放在受保护的服务端配置中。基础闭环不依赖联网模型：解析、单位/期间/口径验证、金额计算、证据定位和问题选择由确定性处理完成。

当时的财报智能解释要求每次新建任务主动勾选，复制或压力测试新任务默认关闭；当前实际发送的观测、规则分析及公开 Agent 独立发送范围以上方“当前模型发送范围”为准。输出需逐项来源 ID，拒绝不存在的引用和金额；这些校验不等于语义正确性证明。调用超时或失败保留规则报告并标示模型未完成。一次公开数据实测完成用时 23,238 毫秒，不承诺固定速度。未选择或未配置时明确显示规则核查。

本项目开发阶段由 AI 工具参与调研、产品与设计决策、代码、数据核对和展示制作；这些判断尚不能归为三位成员已独立完成的贡献。团队醒来后必须复核与理解。实际模型调用、规则模式与开发工具用途在 AI 使用说明中分别披露。

### 7. 技术与接口（早期记录）

选择 TypeScript strict、React/Vite 前端、Express 服务端，单机多账号。Node 22.23.1 已安装，Vite 官方要求 Node 20.19+/22.12+，满足。PDF 使用已核验 pdf-parse 2.x。主要依赖固定到实际安装版本并保留锁文件。

服务端本机绑定 127.0.0.1:4317，前端开发 127.0.0.1:4318；生产构建由服务端同源提供。账号与会话使用 SQLite，每个用户工作区独立原子保存；任务异步执行、保存阶段与输入快照，单进程串行化写入避免覆盖。当前交付支持单进程自托管多用户，不宣称多节点生产集群。上传有格式、大小、内容和路径校验，不远程抓取用户任意 URL，不执行资料中的指令。

密码使用随机盐与 scrypt，服务端只保存哈希；随机会话令牌只保存摘要，Cookie 为 HttpOnly、SameSite，并有过期与注销。写操作校验 CSRF，注册/登录限流。部署时配置实际 HTTPS APP_ORIGIN 与安全 Cookie，反向代理同源，持久卷与备份覆盖账号及工作区。无邮件服务时不显示虚假邮件找回入口。上线前仍需运营方落实域名、TLS、备份、监控、隐私与数据授权；这些条件不冒充已在公网验收。

API 由 shared/contracts.ts 定义：workspace/cases/materials/tasks；创建任务、查看状态/报告、复制与压力测试；更新问题；删除任务/材料；导出；显式重置。错误有中文/英文可呈现码，不将堆栈或密钥返回浏览器。

服务端提供可选模型环境变量，示例不含密钥。日志不保存凭据。启动/关闭/重启、健康检查与数据恢复步骤写入运行文档。用户已授权最终部署到新服务器，公网域名现统一为 `prispect.com`；采用非 root 应用进程、同源 HTTPS、完整状态备份，并以实际部署验收记录确认上线，不能把模板文件视为部署完成。

### 8. 品牌与交互系统（早期记录）

团队与产品统一使用品牌：析光 / Prispect；不用虚构客户、银行合作、奖项或使用量。标识采用原创几何取景框，素材说明记录构成。

当前设计采用 Linear / Apple 的简约方向：石墨文字、系统字体、中性色面和单一蓝色操作。导航退后、内容紧凑、层级统一；不使用标语大字、彩色装饰盒或雷达评分。系统深浅主题自动跟随，打印维持白纸底色。现金桥原文透镜、精确金额、键盘操作和来源抽屉承担实际核查。

两视角分别提供外部交款/信任前核查，以及内部经营交接核查。共同展示资料、已采用事实、现金信号、可能原因、缺少的证据与下一步；材料缺失或口径冲突时相关解释停止。跟进备注独立保存，勾选记录用户处理而非认证。

现金压力沙盘基于用户保存的90天非重叠收付款假设，交互检验回款收回比例、延后30天和额外首期付款；显示期末缺口与最低所需整数回款比例。原年报历史现金流不会冒充当前现金余额或未来收入；未知输入不能补零。交互值不是未来预测、坏账概率或风险评级。

中文与英文核心流程、桌面1440px、手机390px、展屏1920px和768px分别验证。当前新主题/新交互的运行证据与自动化发布状态见acceptance.md；图示计划不代替实际页面。

### 9. 演示案例与异常（早期记录）

- 松原 2025：合并净利润增长、CFO 下降，现金转化约 7.15%。核查应收/存货占款，保留扩产与票据解释；不得断言坏账或爆雷。
- 海康 2025：合并净利润与 CFO 使用正确合并口径，现金转化约 164.18%；用作另一个历史现金结构样本，不写“安全企业”。
- 材料不足：只提供松原头部指标，明确人为限制输入，停止原因归因，请求现金补充表与期后回款。
- 口径冲突：母公司净利润配合并 CFO，真实提示冲突与修复路径。
- 任意规范输入变化：数值改变会引起实际重算，不返回固化报告。
- 无效格式、超限文件、扫描件/无文本 PDF、零/负基数、外部模型超时、刷新与重启均可审查。

### 10. 实施与验收（早期记录）

以目标实际启动为起点规划 6–8 小时，允许因规则/资源调整；不机械耗时。阶段顺序：核验与有限研究（已完成）→方案（本文件）→真实处理与一条运行闭环→完整页面→反例/压力测试→视觉复查→展示文件→验收与提交。尽早集成，避免外围页面先于核心处理。

职责：主线程持有方案、接口、整合、验收与展示；独立研究线程只写研究与来源；后端线程独占 server/ 与处理测试；前端线程独占 src/，不改后端。共享合同由主线程维护，接口改动先沟通，禁止同文件并行覆盖。

验收：两例正常输入、一例缺失、一例冲突；完整入口→注册/登录→新建→真实处理→报告→证据→保存/重开→导出；改密/退出/刷新会话、跨账号读取与写入拒绝、CSRF与登录限流、密码/会话存储；公式/单位/币种/期间、每项结论和引用、刷新/重启持久化、所有路由及可见操作、上传错误与模型失败、typecheck/build/test/format/模板校验、桌面/手机/展屏、浏览器错误、打印实际输出、README 从零启动。

安排独立严格评委审查：贴题、同质化、用户证据、最易追问的原文、演示失败点、超出能力的文案、团队理解能力。以实际产品证据修复，不以模型自评打分代替核验。
