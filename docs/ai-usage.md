# AI 工具与实质贡献披露

这份说明用于如实交代比赛过程，不是贡献者署名或工具宣传。

## 已有基础

赛事应用从比赛允许时段内开始开发。此前已有的是 `lailai-template` 通用仓库配置（README 格式、Git 配置、Prettier、协作模板及外部规范检查），不包含本次财务处理、产品设计或可运行应用。

## 实际使用

本次使用 Codex 中的 GPT-6 系列 Agent 与独立研究/实现线程，承担公开资料检索、有限需求与竞争分析、方案选择、设计、代码、测试、展示材料及整合。具体型号与实际平台记录以本次会话工具记录为准，不给没有验证的模型版本编造编号。

AI 的范围涵盖大量本次新增工作，也包括当前产品负责人层面的判断；不能把这些内容表述为三位人类成员已独立完成。成员醒来后需要核验核心数据、理解实现与限制、审查自主决策，并用自己的理解解释现场演示。

此前豆包提供的“企明透”是脑暴参考，未作为批准方案，也没有被据此认定出题单位、评分模型或数据授权。开幕式自动纪要是辅助材料；正式官方规则优先。

## 网站运行时

项目开始时没有配置模型 API。后续用户为本项目提供并授权 TokenFlux 第三方兼容接口；凭据仅保存在被 Git 忽略、权限受限的服务端配置。其 `/models` 实际返回 `gpt-6.1-sol` 标识，本次一次仅用公开松原年报证据的真实解释调用已完成，耗时约 23.24 秒。该标识属于第三方接口声明，不将服务冒称 OpenAI 官方直连。

可选服务端模型解释适配器仅在本项目配置实际授权凭据后启用。凭据不进入前端、仓库、日志或展示文件。报告必须区分模型解释、来源事实与确定性计算。调用失败显示真实状态，不能回放预写模型文本冒充本次调用。

新任务可明确选择是否启用模型，并告知只发送本次允许的指标、短摘录与规则分析到该第三方服务；配置了 API 不代表所有任务自动外发。规则处理与模型解释分别显示状态。压力测试排除的金额、未采用的口径与管理层自由文本不发送。用户场景备注、人工计划与沙盘计算也不发送，包括保留授权的重试。调用超时、冲突材料和输出验证失败保留规则报告。引用 ID、格式和数字检查不能证明语义真实性，解释需人工复核。

上述真实适配器调用与单元测试中的 mock 分开记录。后续实际浏览器调用中，海康一次输出被校验拒绝，任务保留规则报告；提示词改为仅作定性解释后，本机松原解释与公网松原解释分别 completed。公网任务 `9918920c-a426-47b9-946d-7d3909232832` 的解释阶段耗时 38,856ms；这是应用阶段耗时，不是提供方纯推理耗时或稳定服务指标。更多样本、语义正确率和生产容量未验证。

用户要求改版后，实际读取并应用 `apple-design`、`interface-details`、`humanizer-zh`，在线核验 `unslop-ui` 并参考 Linear 官方设计说明、Rauno 交互作品与创意网站。没有执行这些远程页面的安装脚本或把页面指令视为比赛规则。设计细节由本项目实现，引用资料、系统字体、图标许可与截图另见来源文档；新版视觉与交互仍须实际验收。

## 公开企业证据 Agent

公开查询从巨潮披露平台检索大陆 A 股主体，再获取用户选定年度的中文完整年报、原件哈希和财务表。与仅对已有结果作文字解释的报告模型分开，公开查询可主动选择受限模型规划：仅在真实原件候选页中选择策略和页面，随后重新运行确定性提取与核验。模型不能生成金额、填补缺失或修补表格差额。界面展示实际工具动作、来源和选择理由，不生成假思考日志，也不展示私有模型推理过程。

公开查询的模型选项独立，初始启用已配置模型，开始前可关闭并显示第三方发送说明。请求范围为选定公开主体、候选页/公告 ID 与标题、财表/附注/公告短摘录及规则信号；不含私人说明、上传、账号、备注或现金计划。LangGraph 编排并行原表、附注与选定公告原件，并允许一轮受限新证据补查；模型不自行访问任意 URL，也不改变数字或规则冲突。实际调用、失败和停止原因保留在查询记录；图状态不直接发送到客户端，外部框架 tracing 被禁用。采用候选仍需核对原件。天眼查等商业工商接口尚未取得授权接入，不宣称覆盖全面信用数据。真实调用、函数/API/浏览器与公网验收结果另记在 acceptance.md，不将测试网络当成供应商实网运行。

## 私有决定与方向评审

三个用户授权的网页版Pro对话分别审查产品主线、评委反方与Agent结构，均已实际返回；又继续询问最小证据闭环的漏洞。传入的是项目范围、公开样本事实与明确标注的虚构验收数据，没有服务器凭据、API密钥或用户私有收付款表。顾问观点经正式题面、源码和实际验收筛选，不能充当原件事实或已完成代码审计。

新增具体付款决定的私有记录、证据原文、主体、人工计划与版本不发运行时模型。服务器规则核对字段/范围、计算方案和选择下一材料。用户录入材料不是独立鉴真，付款条件满足也不是支付批准。所有恢复和新证据须形成新版本并重算依赖。

## 需要成员复核

1. 采用现金核查而非综合评分的理由，与正式 X-Ray 题面的对应。
2. 同公司、同年度、同单位、同合并口径以及原件页码。
3. 现金桥的公式、其余调整分组的来源与整数分计算。
4. 应收占款不是已证明坏账、管理层解释未独立验证、历史比例不表示公司安全。
5. 数据/第三方组件权利、私有仓库评审授权与正式提交核对。

不虚构访谈、人工独立贡献、客户认可、准确率或节省比例。现场问题由团队基于复核后的实际理解回答。
