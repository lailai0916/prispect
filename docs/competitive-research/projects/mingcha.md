# 明察Pro：研究工作流与交互报告模板拆解

本报告只评价 `cosinXx/mingcha-pro` 的实际仓库。其与 WebTrace 队伍的对应关系尚未确认。仓库的实际交付是 Agent Skill 与方法论手册，加一个可直接浏览的静态 HTML 报告模板；没有独立公司研究 Web 应用、后端或检索执行器。因此，本文将方法机制和模板运行分别评价，不拿其没有承担的账户、付款或原件采用任务作直接胜负比较。

## 3. 从用户意图到报告的完整链路

1. 宿主 Agent 判断请求是否属于深度研究，按语气选基础/标准/深度，计划10–15/15–20/20–30轮。
2. 清晰主体进入研究；歧义主体建议至少两轮检索给候选差异。文档同时允许无精确匹配时按最接近注册主体推进，这是金融使用中的重大问题。
3. 开搜前拟八项研究方案卡：目标、边界、子问题、维度、关键词、信源、预算、交付形态。
4. 将问题拆成原子查询，先搜索发现，再读原文取证，边搜边追加事实台账。
5. 来源分级、独立链交叉验证、单位/币种/范围/量级/期间检查；主动反方搜索贯穿过程。
6. 4–6专业视角及 Red Team 提出分歧、压力条件和可证伪信号；覆盖充分或无新发现时停止。
7. 输出事实/推论/判断、依据、意义、验证与证伪信号、跟踪变量与易误判点。
8. 以模板填入最终内容，交付本地 HTML。除用户明确要纯文本外，文档要求 HTML。

上述1–7是设计规范及提示词机制，本仓库没有可供追踪的工具调用程序、请求响应、输出数据库或校验代码。第8的界面骨架已实现并可运行，但没有实际填充器。真实检索能否完成、失败如何恢复、生成是否转义、专家是否并行、预算是否真的截止，均取决于宿主，本轮不能据文档认定已验证。

对析光的价值是让研究的目标、边界和未解问题更可核对，并将“怎么搜、为什么信、什么会改变判断”提升为产品机制。不是复制全场景研究规模。析光服务的是现金证据与付款/交接任务，必须保留A股支持边界、原件采用、确定性计算、私密材料隔离以及缺失/冲突停止。

## 4. 用户、动机与决策表达

明察定位广泛的公开研究需求：行业、公司、技术、政策、人物、事件。它承诺给一份固化、可溯源、矛盾明示的报告。用户提供主题后省去人工查询组织和报告排版，最终可把网页交给他人浏览。这是有形交付，易在现场说明“不是十条链接，而是可复核研究”。

长期使用动机主要来自跟踪变量及证伪信号：什么变化会推翻主线。仓库没有定期重查、提醒、历史资料或版本差异实现。研究深度按“快速/深度”语气分档，易理解但不精确：语气不等于决策风险或证据需求，基础档也要10–15轮可能过重。

析光已有直接任务入口和依据按钮，但公开研究的目标仍主要是 `assessmentFocus` 或默认句。可增加一份明确“核查框架”：当前代码/年度/合并范围、现金质量/主体条款/经营变化/反向依据等问题、真实来源覆盖及材料缺口。无真实执行计划记录时必须用“核查框架”，不能宣称模型已经逐项执行。

## 6. 数据、证据与金融方法

有价值的方法细节是：一事实一台账行；已核原文作为重要边界；转载不形成独立链；主体/集团/本体/分部必须分别表述；金额须同时带单位、币种、范围及基期；冲突先保留各说法，再分析范围/时点/独立性，记录采用理由；最新披露未取得要显明。

金融方面主要是研究纪律，无确定性财务公式、评分函数或付款模型。文档“单位、币种、口径、量级、时间”五闸值得程序化；但“净利润大于营收必然错误”不成立，可能存在非经营收益、投资收益或处置收益，应触发复核而非判假。市场值不同时点取区间不能修复时间错配；财年/自然年及分部含AI/不含AI都需要保留其独立范围。

S/A/B/C基于材料性质有启发，但不同文档存在分类不一致：企业官网自述在主方法为B，案例的IR为S、官网新闻稿为A。年报经审计性质与宣传稿不应只凭域名混在一起。来源权重0.9–1.0、结论高>90%等没有统计定义或校准，不转为析光概率。

本仓库没有原件保存、字段采用/撤回、版本依赖、资料真实性认证、独立链自动识别或冲突阻断程序。析光的这些能力应成为承接其研究方法的实际系统保障，而不是退回提示词约束。已有URL/标题去重（`server/company-public-signals.ts:193`）不能证明来源独立性；有必要显示可能同源组和独立性未确认，不能把媒体条目数换为确信百分比。

## 7. Agent与工程可靠性

“稀疏混合注意力”“关键词+语义向量”“多专家并行”属于文档宣称/流程设计。仓库没有embedding调用、检索索引、稀疏召回、多Agent执行器或并发控制。两个来源筛选权重配方和新鲜度规则是手册建议，不是验证过的性能算法；“10倍信息量只增2倍耗时”无基准证据。

工具仅在文本中写 WebSearch/WebFetch，没有接口契约、身份权限、缓存、取消信号、预算计数、请求超时、幂等、错误隔离、恢复或日志持久化。20%反方、≥3独立源、≥2语言、≥40% S/A等均由提示词要求，程序无保证。八阶段再加阶段0更像研究组织框架，不能作为UI自动完成九段进度。

工程价值在静态交付的资源自包含、系统字体、纯CSS/JS轻交互、主题变量、响应式和打印。这些已运行。生产边界在没有安全生成器：说明直接替换 `{{占位符}}`，没有上下文转义或URL白名单；没有可执行填充服务，因此不能认定已确认线上XSS漏洞，但析光若做离线HTML必须独立正确转义。

析光已有真实工具预算、合法ID读取、来源hash、实际计数、账户隔离和失败规则回退（`server/company-research-agent.ts`、`shared/company-assessment.ts`）。可吸收的重点是把执行边界变成用户可核对的框架和覆盖，保留其程序保障；不得展示虚拟专家权威、饱和90%或虚假多源概率。

## 8. 教学、参与、品牌与现场演示

“明察秋毫”与“挖得深，看得清”把品牌锚在研究深度。最容易展示的瞬间是点击“矛盾”直达双方说法，再到来源，并打开事实/推论/判断。报告是可交付对象、折叠是可控探索，降低长研究文本的阅读压力。图表本轮仍是固定占位，不能演示为真实金融结果。

案例走查展示目标→检索→台账→反证→冲突→三层结论，适合转化为准确的金融练习：用户先选现金差异解释，打开原件支持/反方，撤回一条证据，观察依赖暂停，再补资料复盘。析光已有证据实验室和固定挑战，可加入明确“哪些材料会改变判断”的下一步。模板没有互动答题、教学评分或错误反馈，这些是转化设计，未声称对手已有游戏。

小米案例称真实，但没有源URL、日志、hash或完整交付文件；本轮不认证其数字。例子只有18轮，少于深度档20–30的手册标准。其有价值部分是多主体和分部口径提醒、反方检索前置及可证伪条件。不能复制案例数值到析光真实金融材料。

离线模板能在网络失败时保持既有报告可读；不能宣称继续在线研究。析光演示应区分实时检索、已保存快照、公开案例与明确虚构计划；服务失败展示“本轮未完成”、已存依据及恢复入口。用户效果如“更快理解”“减少几次点击”目前是待验证假设，模板操作有效与真实用户效果分开记录。

## 9. 全量价值映射与设计取舍

[mingcha.json](../values/mingcha.json) 登记46项具体价值/待修正机制，覆盖研究、原子查询、时效、预算、聚焦、来源、台账、独立性、反证、改判条件、冲突、主体关系、金额校验、失败边界、视角、停止、标题元数据、KPI、摘要、导航、折叠、打印、离线、图表、时间线、窄屏、明暗、减弱动态、阅读进度、返回顶部、方案比较、字段、导出安全、情景及教程。每项含固定SHA、源码/运行证据、触发、可见/系统行为、问题、价值、代价、析光具体映射、风险、转化、处置与验收。没有已验证吸收标签；模板运行成功与析光后续实现状态分开。

明确拒绝四类：任意置信百分比/固定三独立源配额（MCH-022）；无精确匹配选最相近主体（MCH-023）；硬≥3矛盾/每发现至少一数字（MCH-046）；不将固定图表比例、缺证据案例数字或性能宣称当真实金融成果。后两者的有效结构已进入改造项，不遗漏价值。
