## 核心用户与任务

用户仍是研究假设，尚无真人访谈、需求留存或付费验证。实际产品承接三条相连而不同的任务：

| 任务           | 用户输入与决定                                                                 | 可以输出                                                           | 不能输出                                               |
| -------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------ | ------------------------------------------------------ |
| 公开企业研究   | A 股简称／代码、年度、研究关注点；检查利润与现金、扩展公开线索                 | 同年度合并公开数据、来源关联判断、透明财务筛选、后续问题、原件候选 | 全网工商身份、信用评级、投资结论、当下可用现金         |
| 外部付款前核对 | 交易／收款／退款主体、已付／交付／实际退款、拟付、用户自设上限、条款与来源文本 | 未交付资金敞口、两个条件方案、缺失／冲突门槛、具体材料请求         | 未来退款已到账、公司履行保证、付款批准                 |
| 内部接手核查   | 某日余额、90 天有日期收付事件、刚性／可协商属性、付款日期／现金底线            | 事件余额、首个日末低于底线、同日先付款分支、付款／回款阈值         | 年报货币资金作为当前现金、收款预测、自动授权或协商同意 |

公开财报动机和私有决定依据用 `motivates` 与 `supports` 区分。历史负应收调整可以促使询证某项回款，不能填充该笔回款金额。真实运行的合成事项清楚标为“合成演练供应商（非真实企业）”，不作为真实市场／客户证据。

## 实际端到端路径与数据关系

1. **主体确认。** `shared/company-directory.ts` 与公开 JSON 目录提供 lookup hint；`src/company-search-client.ts` 提供所有者范围的缓存、80ms preloading wait、请求合并、取消和过期。目录候选不能证明目前上市或法定主体。`server/company-sources.ts` 在正式研究时重新通过官方来源核对 code/orgId。成功空候选、来源失败、暂停市场与歧义分别保留。
2. **公开检索。** `server/company-agent.ts` LangGraph 分支读取财务／网页历史／附注／近期原件并复核；每个账号保存断点与原件。公开上下文检索、行业样本、模型深研究有不同预算，不因 UI 进度完成而宣称全部研究完成。
3. **候选采用。** 公司查询结果进入 `CompanyCandidatePreview`。确认单位、年度、合并范围、币种与来源后采用为个人材料。网页 context 不自动成为采用原件；原件 hash 相同时才能复用已核验公开样本摘录。
4. **确定性计算。** `server/engine.ts` 把合并年度 CNY 金额转整数分；利润/CFO 的同口径比例、逐行其余调整、精确现金桥、同比与组合条件来自规则。非正分母、缺失／单位未确认／冲突停止相关解释；原件调整是有符号现金补充表项，不能以资产负债年末变化替代。
5. **公开评估。** `shared/company-assessment.ts` 独立计算 `financial-screen-v1`：盈利成长、现金、偿付杠杆、营运占用四维等权，弱项加评级上限；必要字段缺失／冲突不重分权重。行业／事件只作定性。`shared/company-research-view.ts` 生成中央摘要和实际四阶段读模型，确认 issuer/year/annual scope，并保留旧快照警告。
6. **模型约束。** `server/company-research-agent.ts` 只用固定工具／取得的 ID／主机路径；主体、金额、评级不由模型改写。模型数值用验证过的 metric tokens 渲染；标题不证实事件。反方 review 是独立实际调用而非提示词中的自述；失败保留经过验证的前稿与警告。
7. **私人核查。** `shared/decision-contracts.ts`、`server/decision-engine.ts` 和 `decision-routes.ts` 保存输入／证据的 immutable revision；`baseRevision` 拒绝过期写入。来源文本定位区分 `source-located`／`user-transcribed`／`not-located`，不是鉴真；来源、对方陈述、用户假设不能混用。已知冲突不能靠撤反证或恢复旧版洗掉。
8. **撤回与可恢复。** 原件 lab 是局部暂时依赖试验，不改保存报告。决定证据撤回形成新版本，只让依赖的记录计算未知；独立用户假设不被静默删除或替换。绑定保存文本及 retained original 独立保存，导出 snapshot 和原版文件都保留。
9. **账号与存储。** Better Auth 会话、CSRF、Origin 校验；账号独立 SQLite/working-paper目录。`WorkspaceStore` 原子持久化；需要保留整个数据目录和 auth secret 进行恢复；单进程，不承诺多节点并发。
