## 运行与复现

在仓库根目录运行：

```sh
npm ci
npm run build
node --import tsx scripts/serve-research-demo.ts
```

独立演练默认监听 `http://127.0.0.1:4336/query`，创建新的临时资料目录。使用专门的本机演练账户，不输入真实账户密码。演练脚本拒绝 `NODE_ENV=production`、非空指定目录和外部下载；退出保留资料，不会删除其他目录。

可复现的故障恢复检查：

```sh
node --import tsx --test tests/research-demo.test.ts tests/research-depth-demo.test.ts
```

测试在隔离目录中使用实际 owner HTTP 路由，模拟来源/分析/挑战失败后原路重试。故障参数只通过测试调用 `openResearchDemo(dataDir, faults)` 传入，不是线上配置。不要把失败演练作为成功联网研究或真实 Grok 分析的证据。

## 已完成的实际验收

| 范围             | 实测结果                                                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 研究入口         | 真正输入代码、选择候选、创建本账号研究，取得合成快照并显示规则评级；不是直接打开静态报告                                             |
| 判断与依据       | 依据抽屉显示实际保留字段、精确金额、公式及来源 ID；Esc 返回焦点                                                                      |
| 挑战与局部撤回   | 挑战结果保留零搜索/零模型和未取得材料；撤回存货只暂停实际依赖，恢复回来；API 核对保存的快照和评级未改变                              |
| 来源失败恢复     | 更新时模拟来源失败，旧快照与报告相同；能打开已保存来源覆盖和逐条关系；“重试资料读取”恢复，不伪造成功消息                             |
| 分析与挑战失败   | HTTP 测试证明分析失败不会发布新结论、挑战失败保留旧结果；原路重试恢复，外部请求尝试为 0                                              |
| 问询与回复       | V1 可仅写问题；真实复制和补回复；V2 默认主体/日期来自事项，回复保留问题快照、按陈述分类，不改变敞口或字段核对状态                    |
| 原件关联         | 实际 JSON 文件上传、文本预览、主动确认、文件哈希核对，再主动选择材料/页码关联；V3 明确显示对应字段状态改变                           |
| 付款条件         | 主动补三项角色、条款和金额依据到 V9；输入/记录敞口与数学反求一致，尚缺门槛时记录分支保持未知                                         |
| 撤回、恢复与改问 | V10 撤回退款仅停记录分支；V11 恢复记录演算；V12 改问，此前回复仍保留提交时的问题并能展开                                             |
| 导出与离线       | 预览后实际下载同版 HTML，用 `file://` 打开且阻断网络；问题、回复、摘录和版本可读。该文件不包含原始上传文件，也不代表整个应用离线可用 |
| 布局             | 报告、实验室、问询及付款比较检查了 1440/390/320 像素；浅色与深色代表性页面没有横向溢出；没有发现 JS 页面异常                         |

3 项离线演练测试通过。浏览器过程中的早期失败来自自动化选择器误把折叠内容当缺失、隐式 Select 标签的精确匹配、误等重算抽屉自动关闭，以及阻断了本来需要打开的本机 `file://` 路径。原始记录均保留；纠正脚本后继续验证同一资料与版本，没有通过改产品或清空账户掩盖失败。

主任务的完整项目检查为 779/779 通过，类型、研究资料规范、构建和格式检查均退出 0。最终构建后另外刷新了报告和问询的桌面/390px 深浅主题截图；研究库、材料、新建财报核查和账号设置没有多余的标题说明，导入入口、文本型 PDF/JSON/CSV 和 250MB 实际限制仍可见且可操作。该收尾只验证已经构建的版本，没有重跑完整私有事项或生成新版本。

本轮浏览器文件在 `output/depth-flow/`：`prepare.json`、`core-browser.json`、`private-browser.json`、`finish-private-browser.json`、代表性截图、实际下载的合成 HTML 和哈希清单。`private-browser.json` 保留已走到 V10 的首次中断；后续 `finish-private-browser.json` 接续同一事项，完成恢复、离线和改问。浏览器会话、cookie 和故障文件只保留本机，不提交仓库。

## 验证边界与后续

这是交互、计算、状态和恢复的实际工程验收。没有取得本轮真实 Grok、真实新闻、真实年报全文或其他团队公网部署的成功证明；模拟分析服务失败也不等于已演练真实模型的超时或供应商限流。深入研究的真实模型质量、新闻覆盖、耗时和成本需要在有权使用模型配置的环境运行同输入对照脚本。
