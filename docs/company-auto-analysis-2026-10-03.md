# 结构化数据与后台 AI 分析

日期：2026-10-03。下方记录最终实现的本机验收，不据此宣称真实 Grok 调用或生产已上线。

## 用户动线

新建研究先完成官方主体确认与 F 结构化公开取数，立即展示金额、图表、规则观察和来源。取数阶段没有模型调用、PDF 下载或原件处理。稳定快照保存后，已配置模型的服务端独立排队执行公开 AI 研究；切页不会取消任务，查看数据不依赖报告完成。

研究报告顶部用一个紧凑阶段条展示真实进度与当前动作，不模拟耗时百分比。排队、进行中、部分完成、失败、规则结果与 AI 完整完成保持区别。报告入口为 `section=overview&report=ai`，可返回同一记录的数据页，不新增侧栏栏目。刷新或失败期间保留旧数据和上份报告的原日期与范围。

新金融 AI 报告必须采用核心新格式：100–200 个中文字，先写核心判断，再写重要数字与矛盾，最后写下一步；至少两个不同的模型生成追问，以及 `summaryHighlights` 依据高亮。高亮必须是校验后正文中的原样片段，数字使用已有指标 token，`suggestedQuestions` 绑定可用指标或真实来源。服务器检查核心正文和问题长度、引用、高亮一致性与不同问题数量。保存合同中的字段仍为可选，以兼容缺少它们的旧版缓存报告；这不允许新金融报告省略上述内容。

报告中的推荐问题按钮直接打开并提交到析光助手，带入当前账号的研究记录、年度及显示的利润口径。普通助手建议仍只填草稿，发送推荐问题不覆盖已有草稿；助手忙碌时保留唯一待发送请求。这两个动作不能混淆；会话切换、取消及迟到响应继续遵循账号隔离。

报告问答使用 `reportGeneratedAt` 标记正在阅读的报告版本，并让助手读取同份允许公开发送的报告；版本不符时不能悄悄替换成新报告。该补丁的增量验收仍待完成，不能与前一轮推荐问题交互验收混记。

## 调度与复用

- 稳定快照生成一次自动分析输入哈希，包含主体、年度、快照时间、取数版本和研究重点；失败尝试也记录，同行样本到达不会自动重跑。
- GET、浏览器缓存、重复选择、重访和页面切换读取已有状态，不隐式启动新任务。旧记录缺少报告也不会因为打开而自动补跑。
- 手动更新成功取得新快照后生成新一轮分析；自动失败后需用户明确重试。模型未配置时记录不可用，不追加自动搜索。
- 后台队列共享三个公开来源执行名额，等待队列有容量上限。排队不占用执行名额，不能阻塞已保存财务数据；明确人工启动仍沿用现有并发及每小时 12 次分析限制。
- 原有取消、快照与任务版本栅栏防止迟到结果覆盖更新、删除或重试。中断任务不会在服务重启后悄悄续跑，而是保留已取得资料并明确要求重试。

服务为单进程部署，队列不是跨进程持久任务系统；当前记录持久化不等于已实现多节点任务协调。

## 来源与金融边界

后台研究复用当前允许的公开财务、同行、新闻、帖子、行情与公告来源，必要时继续有界补查。新闻节选、公开讨论和官方摘录的层级保留，模型不能把帖子当作已证实事实。

后续公开 Agent 可以按需读取已有工具允许的官方 PDF 摘录：至多六份、每份 8 MB、45 秒读取期限、仅前三页中的选定摘录，仍在既有总预算内。这与取数阶段禁用 PDF、以及不启动年报原件 LangGraph 管线是不同边界。公开补查不自动采用任何原件；用户上传、私人事项、备注、账户资料和现金计划不进入公司研究模型。

财务金额、指标、评级与弱项限制由确定性规则计算。AI 解释它们并提出后续问题，不重算、改级或编造数字。取数失败不能包装为“公司没有风险”，AI 失败不能阻止读取真实 API 数据。完整工具与预算见[研究 Agent 方法](company-research-agent.md)。

## 验证账本

最终完整 `npm test` 995/995 项通过，0 失败、0 取消、0 跳过，包含自动调度、严格核心格式与助手报告版本绑定回归。严格类型、构建、研究资料检查、全库格式，以及固定模板仓库规范的本机与 `--github` 检查通过。首次 F 整合的历史 934 项结果不作为本轮验收。

实际本机合成浏览器回放 12/12 项通过：API 数据在研究排队时可读，AI 期间同行操作可用；100–200 字正文、重点高亮和三个推荐问题；Esc 关闭与焦点归还；推荐问题自动发送并携带记录、报告版本和合并口径，手动追问继续保持该口径；保留草稿及唯一排队问题；Enter 发送清空输入；忽略其他账号事件；刷新和返回不新增 POST；失败保留上份报告；规则结果不冒充 AI 完成；1366 px 桌面和 390 px 窄屏的深浅主题无横向溢出。
