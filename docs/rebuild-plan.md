# 全站重构方案与验收

本次重构从正式 X-Ray 要求和现有实际能力出发，把分散的企业研究、原件核查、证据实验和私人决定组织成可以连续完成的工作流。代码保存在 `codex/research-workspace-rebuild`，完整本机检查与隔离浏览器回放已通过。真实供应商新研究、私有现金计划的新保存回读及新版本公网发布仍未执行；下文分别记录这些证据层的范围。

## 比赛要求与产品取舍

[比赛规则](rules.md)保留了已核验的题面：从金融视角聚焦一个关键信号，整合分散线索，让普通人看清一家公司的情况。初赛的主题完成度、商业价值与市场需求、创新性、技术运用与实现质量各占 25%；决赛标准尚未知，不据此预测名次。

本次保留利润与经营现金的关系作为清楚可检验的金融入口，再引入同年度财务维度、行业和公开事项。公开讨论用于发现待核问题，不能代替原件。商业价值通过一项能完成的付款或交接核查体现；真实客户需求、付费意愿和节省时间仍需实际验证。

主要取舍：

- 保留 React、严格 TypeScript、Express、现有账户与存储、确定性财务引擎和有界研究流程。重组职责与交互，不为技术栈更换增加迁移风险。
- 一家企业只有一个当前研究入口。摘要、关键判断、证据和后续任务共享明确的主体、年度、口径与快照边界。
- 所有人先读简洁报告，再主动展开专题、公式、原件和研究记录；不恢复“易懂／专业”模式。
- 创新验收集中在真实挑战解释、依赖撤回与材料恢复。搜索、新闻数量、图表和接入模型本身不作为独有创新。

## 信息架构与主工作流

主流程：**查询企业 → 阅读公司报告 → 检验关键判断 → 完成下一项核查 → 保存或进入私人决定。**

主导航为研究库、材料和付款与交接；付款与交接保存本账号私有决定。`/research` 读取当前账号真实的 `company-records`，显示主体、年度、运行状态与可用的轻量结果元数据：摘要、财务等级、时点、过期状态和已保存模型状态。搜索与筛选在本地完成；导航、最近研究和研究库共享按账号隔离的记录订阅，读取列表不启动模型。

| 层级       | 默认内容与行为                                                                 | 深入入口                               |
| ---------- | ------------------------------------------------------------------------------ | -------------------------------------- |
| 查询       | 名称或证券代码、匹配主体、必要歧义确认                                         | 年度等查询选项                         |
| 公司报告   | 主体与年度、简洁摘要、紧凑财务等级、三项关键数值、最多三条重点发现、下一步核查 | 评级依据、专题研究、原件               |
| 专题研究   | 财务历史、同行对比、公告及新闻讨论                                             | 对应来源与覆盖范围                     |
| 证据工作区 | 判断对应的事实、计算、原文和缺口                                               | 挑战解释、本地依赖实验、原件提取与采用 |
| 私人决定   | 可选的预付款或交接任务，明确自设条件与材料                                     | 方案测算、证据变更、历史版本、导出     |

公司主体资料与中央报告分别承担身份和分析职责，同页不再反复呈现同一摘要与等级。中央报告先给合并净利润、经营现金和现金利润比，再给重点发现与下一步。研究过程可展开为取得资料、定向补查、形成判断、反向复核四阶段，各自状态来自实际事件；这是一份只读展示模型，不新增推理或改写等级。

实验室后置为“检验解释”，六维深度、公式、公开数据、询证和原件继续展开。新闻与公开讨论先呈现六条；展开后提供本地关键词、媒体和内容范围筛选、日期排序、十二条分页以及左右列表／所选来源阅读。窄屏保留原文阅读操作，目录筛选不表示重新抓取或阅读所有正文。

现有七个公司页面只在当前企业下显示，原件流程、财报任务和私人决定的深链接继续兼容。来源、覆盖、原件提取与确认仍可深入查看；重组不隐去原有数据与专业能力。旧财报任务保留自身不可变记录。没有“公众／管理者”或“易懂／专业”阅读模式；归母／合并财务口径与外部付款／内部交接目的继续独立保留，原件现金桥保持明确的合并口径。

研究入口保留当前账号草稿，确认匹配主体后开始保存查询；最近研究使用真实账号记录。匿名首页保留标明来源的原件互动例子，事实定位与本地撤证不需要账号或新模型调用。付款情景作为后置、明确标为假设的独立例子。侧栏、顶部导航和文档共用现有设计系统，已载入企业继续支持删除与键盘操作。主题、字号、间距、按钮和状态样式统一；状态颜色只用于明确的小型标记。财务金额不做计数动画，动效尊重减少动态效果设置。

## 架构与数据边界

前端负责逐层展开、导航、来源定位与真实状态反馈；服务端负责账户授权、读取预算、输入校验、计算与持久化。共享合同定义数据边界，避免同一页面分别推导不同版本的结论。

| 数据或动作     | 可用于什么                                         | 必须保留的限制                                                     |
| -------------- | -------------------------------------------------- | ------------------------------------------------------------------ |
| 公开网页快照   | 同主体、同年度的公开财务筛选与专题研究             | 与原件候选及已采用材料分开；缺失或冲突不填零                       |
| 年报原件候选   | 人工核对单位、期间、主体及合并范围后采用           | 提取成功、哈希一致或勾稽闭合不等于鉴真                             |
| 新闻与公开帖子 | 发现事项、整理支持和反向线索                       | 标明标题／短摘录／观点；转发不算独立佐证，不宣称全网或代表性舆情   |
| 规则评级       | 所选年度合并财务的透明筛选                         | 模型不能修改金额、阈值或分数；必要字段不足时不评级，不等同信用评级 |
| 模型判断       | 在实际取得的公开来源上总结、比较解释与提出后续核查 | 引用需可定位；标题不能证明不利事件，不把原因线索写成确定因果       |
| 本地撤证实验   | 查看事实、计算与解释的依赖变化                     | 不改保存报告、评级或采用材料，不向研究模型发送撤回选择             |
| 私人决定与材料 | 本账号的条件测算、证据版本、补件与跟进             | 不发公开研究模型；不把人工计划或陈述混成公司事实                   |

公司公开网页的存货／应收余额变化不能代替现金补充表调整来构造现金桥。历史经营现金不代表今天可用余额，现金利润比不等于销售回款率。集团年报不代替具体合同主体与退款责任。

模型研究保持现有可取消的有界工具能力，不增加无界循环、任意 URL 读取或执行代码。来源、工具尝试、模型调用、缓存、截断和失败均按实际记录展示。当前固定来源及预算详见 [研究方法](company-research-agent.md)；“深入”不靠人为等待或声称暴露模型私密思维。挑战解释与局部撤证的边界见 [证据实验室](evidence-lab.md)。

## 五条体验验收任务

以下能力的重组代码已落盘，部分来源阅读、依赖撤回与恢复、挑战接口契约已检查或回放；五条任务仍需按完整操作范围分别留证。本轮未运行新的真实 Grok 补查，也未执行新的私有现金计划保存后真实回读。隔离接口回放可以检查状态、交互与页面，不证明供应商成功搜索或形成真实新判断。每条需记录精确版本、环境、实际输入、观察结果、证据与通过／失败／未执行状态。使用虚构输入时需显式标明，不形成真实企业预测。

| 任务                    | 操作与可观察的通过条件                                                                                                                                                                                         | 对应初赛要求             |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| 1. 从企业名称到可读报告 | 输入松原安全或证券代码，确认主体；在 2025 合并口径下看到利润与经营现金的关系及核查重点。已核验原件例子的现金利润比为 7.15%，点击金额能定位正确原件页。网页快照若缺失或冲突，显示实际缺口，不能借样例填充       | 主题、实现质量           |
| 2. 挑战当前解释         | 从一项有事实依据的解释发起真实补查，看到实际步骤和来源；结果区分取得的支持线索、反向线索及未取得的区分材料。没有反向线索时如实说明，帖子仍是未核实观点                                                         | 创新、技术运用           |
| 3. 撤回并恢复一条依据   | 在本地依赖实验撤回经营现金或应收事实；仅依赖它的计算／解释暂停，无关事实保留。恢复后重新评估原图；实验前后保存报告、评级和采用材料不变                                                                         | 创新、实现质量           |
| 4. 拒绝混用口径         | 用明确标为测试的材料混入半年 CFO 或母公司净利润；相关比例、现金桥或评级停止，显示需补的期间／范围。更正并采用匹配材料产生新记录或版本，旧结果仍可查看                                                          | 主题、实现质量           |
| 5. 把核查变成具体决定   | 在虚构交接任务中设置 12 万元起点，D10／40／70 各付 10 万、D25 收 20 万、D55／85 各收 12 万，比较 6 万采购 D5 与 D26。两方案期末相同，最低日末分别为 -4 万与 2 万；可绑定材料、撤回、保存并重开，私人计划不外发 | 商业价值、创新、实现质量 |

共同检查：浅色和深色、桌面和窄屏均可读且无整页横向溢出；关键操作可用键盘完成；刷新和重开保留已保存工作；匿名、跨账号和过期任务不能读取或发布另一账号的内容。来源失效、模型未配置、取消或超时应保留已取得信息，并提供实际可用的后续操作。

| 本轮证据层             | 已知状态与范围                                                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 规则与 API 自动检查    | 最终 `npm run check` 通过：类型、448 项测试、构建与全库格式；规范检查也通过                                                      |
| 隔离浏览器与接口回放   | 已检查查询确认、失败重试、摘要与来源、挑战契约、撤证恢复、七页导航、研究库及账号隔离；包含 ≥2 秒慢响应、延迟删除和删除前响应回流 |
| 真实供应商新研究       | 本轮未执行新的付费 Grok 研究，不用回放证明实际取得的新来源或推理效果                                                             |
| 私有任务真实保存与回读 | 本轮未执行新的私有现金计划保存回读，不能只凭计算测试标为完整业务通过                                                             |
| 新版本公网验收         | 未执行；当前线上为回滚后的旧版本                                                                                                 |

## 实施与验收记录原则

| 阶段                         | 当前状态                                         | 完成依据                                      |
| ---------------------------- | ------------------------------------------------ | --------------------------------------------- |
| 比赛要求、现有流程与边界梳理 | 已完成本轮只读梳理                               | 本文引用的规则、方案与源码流程                |
| 信息架构和代码重组           | 已完成；完整本机检查通过                         | 分支差异与完整检查，含文档格式复核            |
| 五条任务、视觉与响应式验收   | 展示与隔离交互已验收；真实新调用与新保存仍未执行 | 下列实际浏览器记录和未执行边界                |
| 本轮真实 Grok 新研究         | 未执行                                           | 供应商真实调用与取得的来源，不用接口回放代替  |
| CI 与公网发布                | 待新版本验证；服务器容量已阻塞                   | 当前提交的 CI、部署结果、服务器版本和关键路径 |

阶段进度只来自真实开始、完成、失败、取消和重试事件。已取得资料可先呈现，最终判断仍需等待对应依据；旧结果与新研究不能混成同一快照。不展示虚构百分比、假调用数量或假“思考中”时间。

类型检查、单元／API 检查、本机浏览器、供应商实际调用和公网部署是不同证据层。每层只说明已检查的范围，不用测试数量推导全部功能、安全或生产容量。本文不生成比赛提交文案、路演材料，也不代正式提交。

本机浏览器记录位于忽略的 `output/playwright/`：`central-workbench/` 保存整站状态、工作流和删除生命周期回放；`rebuild-entry/` 保存输入、私有草稿与按需演算；`rebuild-company-report/` 保存十种报告状态及资料刷新；`rebuild-public-evidence/` 保存来源阅读和来源范围检查。浏览器检查使用真实取得的公开快照及明确隔离的接口响应，不写生产账号、不调用新的付费模型。金额、评级和来源引用保持既有规则，缺失和冲突显示实际限制。
