# 企业研究复用与本地缓存 · 2026-10-03

再次选择已研究企业时，原实现会创建另一份记录，再启动资料和分析。本轮改为打开本账号相同证券代码、orgId、年度及用途的已有记录，优先呈现浏览器保存的公开快照。进入已有研究不会自动补查缺少的资料或分析；首次新建研究的自动流程保留，取新资料和重新分析仍通过各自现有按钮明确触发。

## 实现

- `shared/company-run-reuse.ts` 比较明确输入范围，排除资料缺口与主体不匹配。页面优先采用当前账号的有效记录摘要；列表尚未完成时可以读本地副本，服务器 `reuseExisting:true` 处理无本地副本和并发复用。旧 API 默认创建行为保留，幂等键校验不变，响应 `reused` 不写入工作区。
- `src/company-run-cache.ts` 明确选择已取得公开资料、同行快照和报告，不序列化完整研究对象。原件、候选预览、采用关联、问答、用户目标及原始诊断摘要不持久缓存。副本保留原取得与生成日期；进行中或口径不一致的新状态不覆盖之前的完整副本。
- `localStorage` 上限十二份、总计约 4 MiB UTF-16 存储量、单份约 1.5 MiB；按最近使用淘汰。访问拒绝或配额异常保留有界内存降级，不阻止认证后的服务器读取。副本不因到期自动启动检索。
- 公司页立即呈现缓存，然后通过拥有者 GET 核对记录是否存在并取得已保存服务器状态；此 GET 不调用外部来源或模型。原件等私人内容仍仅通过认证后的读取进入当前页内存。404 或身份失效移除该副本，读取失败保留可读的公开资料与实际错误。
- 删除、成功重置、退出及切换账号清理相应副本；新认证会话可以重新缓存服务器保留记录。成功列表核对只清理请求开始前已有的缓存，防止较早列表误删刚完成的新快照。删除失效标记与跨标签页事件阻止迟到响应重新缓存已移除记录。
