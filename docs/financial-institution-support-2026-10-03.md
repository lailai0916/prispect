# 金融机构取数与分析支持

以本地 `824a5bb` 为修改前版本。银行、证券和保险公司的行业阻断已从公开概览、独立历史财务分支、原件 Agent、六维分析、研究框架及证据实验中移除。原先的历史验收记录仍描述其对应旧版，本记录说明新的支持范围。

## 实现

- 利润表仍读取统一的 `RPT_F10_FINANCE_GINCOME`。校验返回的证券主体、机构代码、机构类型和人民币币种后，用 `ORG_TYPE` 选择银行 `B`、证券 `S`、保险 `I` 或通用 `G` 前缀的现金流量表及资产负债表。
- 独立财务分支仍然只有三次请求：利润表先返回机构类型，余下两张表并行读取。公开概览采用同一选择规则；与新浪的补缺、跨来源金额对照继续保留。未知机构类型不再被一律排除。
- 只映射来源实际提供的字段。银行的现金及存放央行款项不重命名为普通货币资金；缺失的存货、短借等项目不补零。主体、年度、币种、重复金额和跨来源冲突检查保留。
- 先选定保留的最近六个年度及最新季报，再校验相关币种与金额。杭州银行接口还返回二十多年前币种为空的记录，这些窗口外记录不再使最新整张表被拒绝；窗口内的未知或非人民币币种仍然阻断相关表。
- 原件 Agent 不再因简称含银行、证券、保险或信托而提前停止，仍由原件本身的主体、年度、合并范围、单位与表格识别决定候选可用性。
- 金融机构金额与可计算比例进入六维分析、研究框架与证据实验。所有支持的企业使用相同的指标、阈值、评分、结论与后续核查规则；缺少必需字段时保留支持的维度及已有部分评级机制。
- 上下文新增可选 `organizationType`，用于选择取数接口并保留来源信息。金融机构不增加专属说明、判断分支或模型限制；评分、金额及公式仍由统一程序决定。
- 首屏、评级、后续核查和模型输入使用统一流程。同一份金额在银行、证券、保险与其他行业标签下产生相同的报告结果；正常、零值、负值、缺失和冲突状态均有对照回归。

## 验证范围

有意义的回归覆盖：三类机构的动态报表选择与三次请求预算；同年利润和现金保留；缺失字段不填零；主体、机构代码、机构类型、币种及金额冲突仍暂停对应结果；金融机构名称不再阻断年报原件；研究框架及证据实验保留数据。

本机公开财务验收的请求与响应保存在未提交的 `output/financial-institutions/`。公开请求经本环境代理取得精确原始 JSON，再交给真实取数与计算函数；不将 Python 浮点解析结果作为金额输入。非财务来源在该验收中明确拒绝，未核验年报原件或实际模型回答质量。后续浏览器验收使用这些公开响应的缓存，在临时账号与真实 React/Express 页面中检查，不读取生产账号。

旧的空白快照不会自动重写，已有记录需显式更新资料。历史已保存的评级不迁移。本轮本地提交，未推送或部署。
