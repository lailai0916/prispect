# 照见：数据链路与核查边界

本文交接当前实现的数据来源、计算与解释边界。金额一致、引用存在或工具运行成功，都不等于材料鉴真、企业可靠或付款获准。

整数分保证换算与运算精确，不把千元／万元列示的原表升级为精确到分的披露；来源单位与列示精度仍须保留。

## 从公开来源到两种具体核查

| 环节           | 实际实现与保留的信息                                                                                                                                                                                                                      | 停止条件与边界                                                                                                                                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主体与披露检索 | [`searchCompanies`、`listCompanyAnnouncements`](../server/company-sources.ts) 重查官方证券代码与机构 ID；按指定年度选择中文完整年报，另检索近期公告。                                                                                     | 不用相近公司、其他年度或样例替换空结果；金融机构需专门方法。年报主体不自动等于签约、收款或退款主体。                                                                        |
| 原件与文本     | `downloadCompanyPdf` 保存实际下载字节的 SHA-256；[`readCompanyPdf`](../server/company-extraction.ts) 经 [`readPdfIsolated`](../server/pdf-parser.ts) 读取页码与文本；[`WorkspaceStore.retainUpload`](../server/store.ts) 按账号保存原件。 | 哈希证明字节一致，不认证经济事实。当前没有 OCR；解析失败、限流与材料缺失分别保留。子进程是 CPU 隔离，不是操作系统沙盒承诺。                                                 |
| 财务候选       | [`extractFinancialCandidates`](../server/company-extraction.ts) 依本表主体、合并范围、年度列头、单位和原始行提取候选，保留页码、摘录与其余调整的逐行组件。千元等换算后仍保留原单位。                                                      | 未确认单位、表头、范围或跨页续表就缺项；不能借另一张表的上下文。预置案例仅在实际下载原件哈希匹配时复用已核验摘录。所有查询候选仍需用户确认采用。                            |
| 确定性规则     | [`analyze`](../server/engine.ts) 使用 [`moneyToFen`](../server/validation.ts) 转整数分；比率为同年度合并经营现金净额÷合并净利润，净利润非正时不报通常比率。现金桥要求原始调整行与披露 CFO 精确相合。                                      | 不将归母利润混入合并 CFO，不把年度比率称作回款率。缺值不填零；口径冲突停相关计算；不以残差凑平。宁德 2025 年原表行和差 2,000 元仍保留并停止桥，可能的列示精度原因未经确认。 |
| 公开解释与补查 | [`runCompanyResearch`](../server/company-agent.ts) 的 LangGraph 分支执行财务、附注、近期全文读取与汇总。模型只在提供的页或公告 ID 中选择补查、引用原文提出竞争解释；真实请求、失败与覆盖范围写入工具轨迹。                                | 模型不能写入财务金额或用叙述解除冲突。未读取的标题不是已核验事实，关键词不是风险评级。引用 ID 与格式检查不等于含义验证。模型失败保留规则和已读原文。                        |
| 外部交款核查   | [`evaluateDecision`](../server/decision-engine.ts) 分别检查签约、收款、退款责任主体与条款；计算两种拟付款条件下的未交付敞口，区分已付、实际交付、已到账退款和承诺。                                                                       | 保存文本中的字段定位仅为 `source-located`，不叫鉴真；无绑定原文的转录不变成记录依据。未来退款、未到账承诺不抵减实际敞口。金额可算不代表上限已知或可以支付。                 |
| 内部接任核查   | [`calculateDatedCash`、`compareDatedCash`](../shared/decision-cash.ts) 按私人日期事件计算余额、首个期末缺口、同日收付次序敏感性与最多两方案。历史财务信号只以 `motivates` 连接具体收款的下一核查。                                        | 年报 CFO 不填当前现金。用户计划是条件，直接记录支持各自字段；撤回必要余额或支出依据使记录分支未知，不删除支出或提高上限。独立假设分支仍保留，并明确其条件。                 |

## 权限、版本与模型边界

[`company-routes.ts`](../server/company-routes.ts)、[`decision-routes.ts`](../server/decision-routes.ts) 和 `WorkspaceStore` 将材料、任务、原件、公开查询断点与决定版本隔离到当前账号；写请求受会话、CSRF 与 Origin 校验。新账号为空，重置不预装样例。用户确认候选或标记完成，不认证材料真实性。

决定更新以 `baseRevision` 防覆盖；撤回、恢复和适用主体／日期更正均生成新版本。旧输入回放与当前已知冲突区分，恢复旧版本不能洗掉后来的反证；仍被版本引用的材料与报告不能直接删除。财报任务保留输入快照；人为排除指标不从剩余文本暗中补回，也不发给解释模型。

公开企业 Agent 只向模型发送所查询公司的公开元数据、候选页与已读短原文；私人交易记录、现金计划、跟进备注和账号数据不进入该载荷。财报任务的 [`explainWithModel`](../server/model.ts) 另需显式选择，仅发送已采用的本期与比较年度合并指标、短摘录、规则结论及非管理层解释的规则分析；不发送整份文件或未采用、排除、冲突观测。前端的 [`parseCashPlanImport`](../shared/cash-plan-import.ts) 在本地解析 CSV／JSON，确认后只是计划条件，不自动生成来源记录。

## 工程承诺如何核对

开发中的分工和交叉审查、运行时的多分支编排是两件事。运行分支共享公开证据与模型配置；开发审查也不能保证所有参与者使用不同模型、完全无历史上下文。因此本项目不宣称独立金融审计或叙述完全无误。可复核的保证来自金额写入路径、类型与范围验证、原件、逐行求和和反例测试；模型仍可能选错线索，提取规则仍需更多发行人验证。参考项目的公式、覆盖、速度与测试计数不属于本项目证据，公式取舍另见[参考数据审查](reference-data-review.md)。
