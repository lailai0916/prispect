# 照见 CashLens：三位成员理解与排练指南

版本日期：2026-10-02（北京时间）。这是成员学习、核对与实际排练用的指南，不是三人已经掌握或独立贡献的证明。只填写确实做过的工作。

当前主线是两项具体付款任务：**替家人核对预付款；接手公司后核对新增付款。** 公开年报、现金桥与Agent是它们按需使用的工具。系统核对的是当前资料能支持什么、什么仍是承诺或假设、下一项需要什么材料；没有银行鉴真、合同法律审查或企业安全认证。

网站与真实验证状态以 [acceptance.md](acceptance.md) 为准。本轮功能0c3590176760b68f06f6e1163e907e34ee174b5a已通过CI、自动部署和公网决定流验收；独立复验79/79断言通过。PDF/视频按最新长期目标完成新版制作，旧候选不算本轮成品；封面和提交文案不制作，也不代为赛事提交。

## 每个人都要解释清楚的七件事

1. **为什么从一笔决定开始。** 普通人不是要读遍全部年报，而是要知道这笔钱的主体、付款条件和哪些证据仍缺。内部接手者需要知道哪天付款受什么约束。两种视角控制的资金和所需资料不同。
2. **什么是依据。** 原文记载、对方陈述、情景假设、程序计算分开。绑定材料后的“原文已定位”只表示有限的主体、日期、金额与收付方向字段检查；用户转录或上传原文不能证明文件真实、完整语义或对方一定履行。哈希绑定文件内容版本，不鉴真。勾选跟进只记录处理状态。
3. **证据如何改变结论。** 同一范围同槽的来源反证保留冲突；撤回当前余额依据使有记录的现金路径未知，但明确输入的假设测算和独立年报事实仍可读。撤工资依据不能把工资当0。每次恢复均产生新版本；主体/日期更正不能改金额、原文、角色或收付方向，旧版仍保留，恢复旧范围会重新评估并重开适用冲突。
4. **比例是什么。** CFO/合并净利润是年度列报金额关系，不是销售回款率、退款成功率、信用等级或沙盘回款比例。高比例也不能绕过当前付款条件。
5. **未知怎样处理。** 缺余额、金额或日期不补0、不从历史年报填当前余额；只月度数据不能承诺月内无缺口；同日次序未知需要单列先付款保守分支。
6. **Agent做什么。** 公开主体与报告检索、下载、哈希、实际候选页规划、规则复核以及真实停止。金额与私有决定由程序算，模型不能编数、兜平或批准付款。模型不可用时仍可重算已有私有输入。
7. **什么还没证明。** 具体场景测试不是全市场准确率；商业需求/付费没有真人验证；非上市企业当前财务、银行真假、法律效力和未来履约不在已证范围。集团年报只提示历史待核问题，不是当前付款的必备材料，也不替合同主体承担责任。

## 两条能用纸笔解释的验收任务

以下交易与计划全是**虚构验收输入**，没有声称真实上市公司会发生这些付款。

外部：总额10万元；明确录入已付、已交付对应金额、实际退款均0；全付10万与条件首付2万；本人设未交付敞口上限2万。

```text
情景敞口=max(0,已付+拟付−交付对应金额−实际退款)
全付：10万；首付：2万
```

前者超过自设上限，后者在所设未交付情景下等于上限。2万来自用户的约束，不是AI安全额度；对方未接受分期条款时方案仍待核查。退款承诺不是实际退款。集团历史财报不能替子公司的履约责任和当前资金提供依据。非上市企业仍可记录拟签合同、收款指引与付款条件，但不伪造该企业财务。

内部：起点12万；D10/40/70各付10万；D25收20万、D55/85各收12万；待决定采购6万，比较D5与D26。

| 结果         |      D5付款 | D26付款 |
| ------------ | ----------: | ------: |
| D30期末      |        16万 |    16万 |
| D60期末      |        18万 |    18万 |
| D90期末      |        20万 |    20万 |
| 最低事件余额 | −4万（D10） |     2万 |

月末都有钱不等于付款日赶得上。原基线满足0底线时，D5新增付款的数学上限是2万；这不是经营预算或批准。D26方案在当前日期、其他付款、先付款保守次序不变时，最低整数回款比例75%；74%会在D70缺3200元。该比例不是预测。提高D25回款不能解决D10已经发生的缺口。

测算基准日是 D0，次日为 D1。显示的首次缺口是已列事件日末低于用户底线；同日有收有付时，先付款的保守分支可能为负，即使日末为正。底线是用户自设约束，不等于破产界线。起点或原计划已低于底线时，不能拿逆向金额说新增付款可行。未列的义务、未来未兑现的回款或未经同意的改期都会改变结果。

财报页面仍有三段 30/60/90 天工作表和比例、延后 30 天、额外付款压力测试；它们只推出区间期末，不知道月内发生日。付款决定的日期事件测算是另一条明确日期的规则链。不能将三段结果解释成逐日安全，也不能把日期计划说成企业未来真实现金。

## 三分钟实际操作顺序

1. 从首页选任务，载入明确标注的虚构输入；先说清对象、金额、日期、用户约束。
2. 展开原文与依赖，说明哪项是记录、哪项是承诺、哪项是假设。
3. 让评委选择撤回必要依据；观察只有相关输出退回未知，无关历史事实保留。
4. 补回相关材料，或先补一份主体/日期不匹配材料，展示不同结果；看新版本与旧版。
5. 内部改采购日期，看到相同期末但不同期间最低值；外部改首付金额，看到自己的暴露与尚缺条件。
6. 若被追问，再打开公共Agent真实完成记录及宁德2000元差异；不把历史记录冒充现场抓取。未知报告不保证三分钟完成。

## 面对竞品与严格追问

天眼查已公开声明财务深评、尽调、Agent及合同建议。我们不能说它只提供查询；ChatGPT加搜索也能分析公司。我们的可证明取舍是默认施加主体/时点/来源约束，版本化地局部撤回和恢复，按日期与自设条件确定性重算。别人可以复现这一流程；本次提交的是可操作产品，不是不可复制的基础技术。

用户上传假材料时，本产品可能在所供输入下计算，所以所有字段匹配都不等于真实性认证。正期末、哈希、金额对平和模型解释都不能单独证明可靠。系统给出的是条件与材料缺口，人仍作决定；工具不执行付款、不发送补件。

三位建议分工：A讲具体任务与范围，B找原件并手算，C操作版本、现金日期与模型边界。每人都需要亲手走通两条任务，不能把全部财务或技术问题推给一个人。

## 核心公式：先会手算，再讲图

固定现金桥：

```text
合并净利润
+ 存货现金桥调整
+ 经营性应收现金桥调整
+ 经营性应付现金桥调整
+ 其余已披露调整分组
= 合并经营活动现金流量净额（CFO）
```

这些调整来自现金流补充表，不直接等于资产负债表对应科目的期末减期初。经营性应收也不等于单一应收账款。正负号按原表使用：原表存货增加相关调整为负，表示该桥步骤减少从利润推到现金的金额；不能直接据此断言库存滞销。

松原 2025 的同年度合并数据，均为人民币元：

| 项目               |            金额 | 来源或属性                                                     |
| ------------------ | --------------: | -------------------------------------------------------------- |
| 合并净利润         |  366,373,098.93 | 正式年报合并现金补充表                                         |
| 存货调整           | -321,030,062.96 | 同一补充表                                                     |
| 经营性应收调整     | -514,221,076.54 | 同一补充表                                                     |
| 经营性应付调整     |  277,839,624.95 | 同一补充表                                                     |
| 其余已披露调整分组 |  217,235,539.32 | 由原表剩余已列示调整独立求和；再与残差核对，不是原文单行“其他” |
| CFO                |   26,197,123.70 | 正式年报合并现金补充表                                         |

原件：[松原 2025 年报](https://static.cninfo.com.cn/finalpage/2026-04-11/1225095334.PDF)，2026-04-11 披露，PDF/印刷第 190–191 页。出处、哈希与完整核验范围见 [research.md](research.md) 和 [source-manifest](../data/source-manifest.json)。

```text
现金转化比例 = 26,197,123.70 / 366,373,098.93 ≈ 7.15%
其余调整残差 = CFO - 合并净利润 - 存货调整 - 应收调整 - 应付调整
```

完整原表存在时，残差应与其余已列示行的独立求和比较。只有残差、没有这些证据时，只能显示未归因差额，不能称已解释的其他调整。桥闭合只说明金额关系能核对，不能证明管理层解释、客户回款或企业可靠性。

同比增长率需要可比期间且基数为正。零或负基数应报告金额变化，避免普通增长率误导。净利润不为正时，不作常规现金转化比例解读。缺少 2024 比较数据时，不称 2025 利润增长。

## 四个口径不能混

| 项目       | 必须核对什么                                | 容易出现的错误                                                                     |
| ---------- | ------------------------------------------- | ---------------------------------------------------------------------------------- |
| 主体范围   | 同一公司、合并报表                          | 把母公司利润或归母净利润与合并 CFO 混算                                            |
| 期间       | 同一年度、明确 annual 与相应年份            | 同是 2025 的半年数字与全年数字混算                                                 |
| 货币与单位 | 币种及元/千元/万元/亿元明确，按本表单位转换 | 原件千元或万元当元；看到人民币就忽略每张表的单位；把程序整数分当成原披露的分级精度 |
| 指标定义   | 净利润、经营现金净额及具体桥调整            | 把经营现金净额当经营流入，把经营性应收调整当应收账款余额变化                       |

海康 2025 合并净利润为 15,433,655,239.83 元，归母净利润为 14,195,371,894.42 元，二者不同。合并 CFO 为 25,339,411,083.10 元，应与前一个合并净利润核对，比例约 164.18%。原件：[海康 2025 年报](https://static.cninfo.com.cn/finalpage/2026-04-18/1225123062.PDF)，2026-04-18 披露，合并补充表 PDF 第 229 页/印刷第 228 页；PDF 第 260 页是母公司补充表。164.18% 不能说明企业安全，两家不同行业样本也不形成健康排名。

宁德时代是非预置样本的真实公开查询案例。[宁德 2025 年报](https://static.cninfo.com.cn/finalpage/2026-03-10/1225002214.PDF) 于 2026-03-10 披露，合并现金补充表跨 PDF 第 200–201 页，单位为人民币千元。2025 合并净利润 76,786,309 千元、CFO 133,219,982 千元；原始调整行独立求和后的桥为 133,219,980 千元，差 2 千元，即 2,000 元。系统保留差异并停止完整桥及依赖解释，不增加“其他”把桥凑平。披露精度可能有关，但原因尚未证实，差异也不证明造假。千元会显式换算为元，原文单位保留，整数分运算不提高原披露精度。

该次实际查询保留了两年 12 条观测与每年 14 个其余调整组成，2024 桥能核对；这些成功与停止记录不证明任意公司、任意年度或扫描 PDF 均可处理。公开 Agent 先要求确认巨潮大陆 A 股主体；无匹配不等于企业不存在，近期公告标题也不等于完整风险调查。

## 证据分层与询证

| 类别           | 例子                                   | 能怎样讲                                        |
| -------------- | -------------------------------------- | ----------------------------------------------- |
| 原文事实       | 正式年报列示金额、期间、合并表名       | 指出来源、表、页码和日期                        |
| 派生计算       | 比例、同比变化、现金桥分组             | 给出公式及输入；可重算                          |
| 管理层说法     | 松原关于票据结算、扩产、客户逾期的解释 | “公司披露/解释”；我们未用客户流水或函证独立验证 |
| 待验证经营解释 | 扩张备货、结算时点变化或回款/去化压力  | 提出竞争解释与需要的资料，不直接下结论          |
| 产品与市场假设 | 采购负责人愿意使用并付费               | 承认没有真人访谈和付费验证                      |

具体问题的结构是“哪家公司、哪个期间、哪笔调整、为什么仍不确定、需要什么资料”。例如针对松原 2025 经营性应收调整，可请求相应构成明细、票据结算情况、账龄及期后回款，以区分结算结构变化与回款压力。所需材料可能非公开，工具不能虚构或绕过权限取得。

## 技术流程，用普通话解释

```text
付款决定：
输入具体交易或日期计划 → 服务端确认会话与当前用户 → 保存输入版本
→ 绑定本账号材料中的原文字段 → 区分来源记录、陈述与假设
→ 检查范围/冲突 → 局部条件、补件、假设与有记录测算分别呈现
→ 撤回/恢复/范围更正另存版本 → 阅读历史或恢复为新版本并重新评估

公开证据与财报工具（按需）：
确认公司主体 → 获取官方年报/PDF/哈希/实际工具记录 → 核对候选后采用
→ 校验合并范围、年度、单位与原行差异 → 计算支持的现金桥与问题
→ 保存、原件定位、跟进、比较、HTML/JSON导出
```

技术方案使用 TypeScript、React/Vite 前端和 Express 服务端；账号/会话使用 SQLite，工作区按用户隔离保存。实际交付能力由实现和测试记录确认，技术名词本身不证明安全或创新。

账号不能只靠前端隐藏别人数据：服务端要从有效会话确认用户，每个读取、修改、删除与导出都校验归属。受控 A/B 测试需要直接访问对方已知 ID。Cookie、密码哈希、注销、CSRF 和限流是需要逐项验证的实现点，不能笼统称经过安全认证。该方案是单机多账号，不承诺分布式企业集群。

规范 JSON/CSV 和可处理的文本 PDF 是财报输入范围。早期独立上传测试用松原全文 PDF 提取了 12 条 2025/2024 观察；该次上传日期字段默认上传日，需要人工改成公告日并核对出处，确认后的原件字节数与 SHA-256 匹配本机文件。这是该样本的历史测试记录，不证明任意 PDF 可用；没有扫描件 OCR 能力，该次独立复核也未复测 CSV。公开 Agent 使用公告披露日期与实际下载原件，候选仍需确认。格式一致及桥闭合不等于上传内容经过真实性核验。

成员应亲手做一次新数值测试：在明确标为合成数据的 JSON 中使用万元单位，利润 1000 万、CFO 600 万应得到 60%，不要伪称公司事实；再将 CFO 改为半年，报告应拒绝与全年利润混算。原件保留、引用材料禁止删除和任务保存是继续工作所需的产品行为，不证明数据来源真实性。

## AI 参与怎样如实说明

开发中 AI 工具参与了资料研究、方案、交互与代码、核验辅助、测试编写和文稿准备。文件中的判断仍需成员复核。不能把“我看过生成结果”直接称为独立设计，也不能因为有充足聊天额度就声称网站配置了模型 API。

运行时的金额、口径、依赖与私有决定由服务端确定性规则处理。模型默认关闭；财报解释和公开企业 Agent 分别主动选择。第三方 TokenFlux（`tokenflux.dev`）的两类发送范围不同：

- 财报解释：本次采用观测的 `id/key/year/value/unit/currency/scope/quote`，加 `verdict` 及非管理层说法的规则分析 `deterministicFindings`（`id/label/explanation/basis`）。撤回、冲突与未采用观测不发；不能只说发送了金额和摘录。公司名、来源 URL 和原件全文不是该解释请求的单独字段。
- 公开 Agent：规划发送公开公司代码/名称 `identity`、`reportTitle`、`requestedYear`、已下载白名单页 `publicPages` 的信息与短摘录、`actionBudget`。模型只选择实际页和动作；程序在所选范围真实重提取及比较，不把模型金额当证据。后续公开解释沿用上项字段，冲突时停止解释。
- 私有付款决定的输入、交易记录、材料原文、备注和日期现金计划不发送外部模型。账号密码、会话也不作为模型分析材料。授权某次财报解释不等于授权发送私有决定材料。

解释通常设单次 60 秒超时，配置上限 90 秒；公开 Agent 模型阶段使用另一个 60 秒共享预算、最多三次调用，整个查询有 150 秒超时。它们不保证每次现场完成；实际发送及停止边界以对应适配器和测试记录为准，页面文案不是完整隐私认证。

主线程记录一次公开财报真实调用完成，耗时 23,238 ms，返回服务标识 `gpt-6.1-sol`；新提示词的一次真实 UI 流程 explain→save 为 43,720 ms。这两项计时范围不同，第三方延迟浮动，不是固定速度承诺；此前失败记录也保留。只能据此说明该第三方服务真实返回结果，没有独立验证上游型号，也不是 OpenAI 官方直连接入。独立评审自己的任务都未勾选模型，尤其合成 QA 数据没有外发。mock 不是供应商推理，引用 ID 与数字格式检查不等于语义事实全部正确。调用失败或未选择时，按报告的实际状态说明规则结果。

真实人类贡献可按记录描述，例如“核对原件某页与三个金额”“修改某条错误文案”“复现 A/B 越权拒绝”“完成某次真人任务测试”。只填写确实做过的内容；没有访谈、客户或独立代码贡献就不补写。
