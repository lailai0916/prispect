# 照见 CashLens：三位成员理解与排练指南

版本日期：2026-10-01（北京时间）。这是需要成员实际学习、核对与演练的指南，不是已经掌握或已贡献的证明。三位成员没有在本文中被假定具有财务、开发或用户研究经验。角色建议可交换；提交时按真实行动填写姓名与贡献。

主线程报告 typecheck 与 16 项单元/API 测试通过；本文未独立复跑。构建、浏览器、公开部署及视频尚未完成验收。不能因后端测试通过就对评委声称完整产品、全部安全或企业上线条件已经通过。

## 每个人都要解释清楚的五件事

1. **我们核查什么。** 固定核查同年度合并净利润与经营现金净额的金额关系，重建有来源的现金桥，生成具体补件问题。任务标题不是任意语义真假判断输入。
2. **比例是什么。** CFO / 合并净利润是现金与利润的金额关系，不是销售回款率、信用等级或违约概率。
3. **证据不足怎样处理。** 缺失不是零；头部金额仍可成立，但失去材料支持的桥步骤和经营归因必须撤回。补回材料后仅恢复它能支持的部分。
4. **什么已经证明。** 正式年报中的金额、算术关系和具体测试场景各有自己的证据；管理层说法、经营原因、目标用户需求与商用数据权限不能一起当成已确认事实。
5. **AI 做了什么。** 开发辅助与网站运行时模型是两件事。未实际配置并成功调用 API 时，网站按规则分析介绍。生成的方案和代码不能自动算成成员独立贡献。

## 核心公式：先会手算，再讲图

固定现金桥：

```text
合并净利润
+ 存货现金桥调整
+ 经营性应收现金桥调整
+ 经营性应付现金桥调整
+ 其余已披露调整分组
= 合并经营活动现金流量净额（CFO）
```

这些调整来自现金流补充表，不直接等于资产负债表对应科目的期末减期初。经营性应收也不等于单一应收账款。正负号按原表使用：原表存货增加相关调整为负，表示该桥步骤减少从利润推到现金的金额；不能直接据此断言库存滞销。

松原 2025 的同年度合并数据，均为人民币元：

| 项目               |            金额 | 来源或属性                                                     |
| ------------------ | --------------: | -------------------------------------------------------------- |
| 合并净利润         |  366,373,098.93 | 正式年报合并现金补充表                                         |
| 存货调整           | -321,030,062.96 | 同一补充表                                                     |
| 经营性应收调整     | -514,221,076.54 | 同一补充表                                                     |
| 经营性应付调整     |  277,839,624.95 | 同一补充表                                                     |
| 其余已披露调整分组 |  217,235,539.32 | 由原表剩余已列示调整独立求和；再与残差核对，不是原文单行“其他” |
| CFO                |   26,197,123.70 | 正式年报合并现金补充表                                         |

原件：[松原 2025 年报](https://static.cninfo.com.cn/finalpage/2026-04-11/1225095334.PDF)，2026-04-11 披露，PDF/印刷第 190–191 页。出处、哈希与完整核验范围见 [research.md](research.md) 和 [source-manifest](../data/source-manifest.json)。

```text
现金转化比例 = 26,197,123.70 / 366,373,098.93 ≈ 7.15%
其余调整残差 = CFO - 合并净利润 - 存货调整 - 应收调整 - 应付调整
```

完整原表存在时，残差应与其余已列示行的独立求和比较。只有残差、没有这些证据时，只能显示未归因差额，不能称已解释的其他调整。桥闭合只说明金额关系能核对，不能证明管理层解释、客户回款或企业可靠性。

同比增长率需要可比期间且基数为正。零或负基数应报告金额变化，避免普通增长率误导。净利润不为正时，不作常规现金转化比例解读。缺少 2024 比较数据时，不称 2025 利润增长。

## 四个口径不能混

| 项目       | 必须核对什么                         | 容易出现的错误                                               |
| ---------- | ------------------------------------ | ------------------------------------------------------------ |
| 主体范围   | 同一公司、合并报表                   | 把母公司利润或归母净利润与合并 CFO 混算                      |
| 期间       | 同一年度、明确 annual 与相应年份     | 同是 2025 的半年数字与全年数字混算                           |
| 货币与单位 | 币种和元/万元/亿元明确，计算统一转换 | 原件万元当元；看到人民币就忽略每张表的单位                   |
| 指标定义   | 净利润、经营现金净额及具体桥调整     | 把经营现金净额当经营流入，把经营性应收调整当应收账款余额变化 |

海康 2025 合并净利润为 15,433,655,239.83 元，归母净利润为 14,195,371,894.42 元，二者不同。合并 CFO 为 25,339,411,083.10 元，应与前一个合并净利润核对，比例约 164.18%。原件：[海康 2025 年报](https://static.cninfo.com.cn/finalpage/2026-04-18/1225123062.PDF)，2026-04-18 披露，合并补充表 PDF 第 229 页/印刷第 228 页；PDF 第 260 页是母公司补充表。164.18% 不能说明企业安全，两家不同行业样本也不形成健康排名。

## 证据分层与询证

| 类别           | 例子                                   | 能怎样讲                                        |
| -------------- | -------------------------------------- | ----------------------------------------------- |
| 原文事实       | 正式年报列示金额、期间、合并表名       | 指出来源、表、页码和日期                        |
| 派生计算       | 比例、同比变化、现金桥分组             | 给出公式及输入；可重算                          |
| 管理层说法     | 松原关于票据结算、扩产、客户逾期的解释 | “公司披露/解释”；我们未用客户流水或函证独立验证 |
| 待验证经营解释 | 扩张备货、结算时点变化或回款/去化压力  | 提出竞争解释与需要的资料，不直接下结论          |
| 产品与市场假设 | 采购负责人愿意使用并付费               | 承认没有真人访谈和付费验证                      |

具体问题的结构是“哪家公司、哪个期间、哪笔调整、为什么仍不确定、需要什么资料”。例如针对松原 2025 经营性应收调整，可请求相应构成明细、票据结算情况、账龄及期后回款，以区分结算结构变化与回款压力。所需材料可能非公开，工具不能虚构或绕过权限取得。

## 三个建议角色，各自必须真懂什么

| 建议角色          | 排练与核对任务                                                                                 | 必须能独立回答                                                           |
| ----------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| A：主讲与业务范围 | 读规则、研究和讲稿；解释固定用户任务、商业假设与已有竞品；核对提交材料和实际成员贡献           | 为什么选这个任务？有什么证据说明价值？什么还没验证？为何不承诺获奖？     |
| B：数据与原件     | 手算一条桥；独立打开两份原件正确页；核对合并/归母/母公司、年度、单位；操作撤证据与补件         | 7.15% 是什么？其余调整怎么来？撤证据后还成立什么？补回后为什么仍有疑问？ |
| C：操作与技术边界 | 从实际首页到账号、导入、任务、保存、导出；学习服务端流程、测试记录和运行模式；准备真实失败说明 | 数据在哪里保存？账号怎么隔离？模型有没有调用？测试证明了哪些场景？       |

这是建议分工，不是已经完成的分工。每个人还需至少走通一次完整核查链路；现场不能把所有口径与出处问题都推给单一成员。

## 技术流程，用普通话解释

```text
浏览器界面
→ 服务端确认会话与当前用户
→ 上传/选择材料，预览并确认口径
→ 保存该用户的材料和任务输入
→ 校验期间、范围、单位及冲突
→ 按本次允许证据计算现金桥、检查与问题
→ 保存报告和问题状态
→ 重开、比较或导出底稿
```

技术方案使用 TypeScript、React/Vite 前端和 Express 服务端；账号/会话使用 SQLite，工作区按用户隔离保存。实际交付能力由实现和测试记录确认，技术名词本身不证明安全或创新。

账号不能只靠前端隐藏别人数据：服务端要从有效会话确认用户，每个读取、修改、删除与导出都校验归属。受控 A/B 测试需要直接访问对方已知 ID。Cookie、密码哈希、注销、CSRF 和限流是需要逐项验证的实现点，不能笼统称经过安全认证。该方案是单机多账号，不承诺分布式企业集群。

规范 JSON/CSV 和可处理的文本 PDF 是输入范围。PDF 提取后的字段仍需确认；不确定表名、单位或期间不能猜。格式一致及桥闭合不等于用户上传内容已经与真实原件独立匹配。

## AI 参与怎样如实说明

开发中 AI 工具参与了资料研究、方案、交互与代码、核验辅助、测试编写和文稿准备。文件中的判断仍需成员复核。不能把“我看过生成结果”直接称为独立设计，也不能因为有充足聊天额度就声称网站配置了模型 API。

运行时的解析、口径检查、金额核算和证据筛选由确定性处理承担。可选解释适配器只有在本项目真实配置 API 并完成调用时才产生模型解释。模型 mock 测试不是供应商真实推理调用；引用 ID 与数字格式检查也不等于语义事实全部正确。无 API 时按规则分析介绍。

真实人类贡献可按记录描述，例如“核对原件某页与三个金额”“修改某条错误文案”“复现 A/B 越权拒绝”“完成某次真人任务测试”。只填写确实做过的内容；没有访谈、客户或独立代码贡献就不补写。

## 每人十分钟的理解检查

以下是排练问题，完成时间只是建议，不是假定已经完成：

- 在不看讲稿时，用一句话定义固定任务；解释标题为何不是任意真假核查。
- 打开松原原件，找到净利润与 CFO，并解释正负调整；手算或用独立表格核对结果。
- 说明为何海康必须用合并净利润，指出合并与母公司表的不同页。
- 解释“撤去调整项后哪些事实保留”，亲手建新任务并明确补回材料。
- 指出一个具体问题需要哪份材料，为什么公开年报不能替代它。
- 说明当前运行模式及实际测试/部署状态；区分开发辅助、规则分析、模型 mock 和真实模型调用。
- 如实列出自己已经完成的两项行动；如果尚无，先完成复核或操作再记录。
