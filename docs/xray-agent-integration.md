# 队友 XRay-Agent 原型审查与合并记录

审查日期：2026-10-02。输入为队友提供的 `XRay-Agent/` 文件夹：`README.md`、`xray_agent.py`、`index.html`、`data/companies.json` 和 `run.bat`。这是参考原型，不是已接入的真实数据供应商。

## 核查结果

原型用五家明确标作虚构的公司展示财务、信用、口碑、交叉规则与快速对照。其最有用的产品表达是：多项异常一起出现时，明确写出组合条件与下一步该取的材料；评委能迅速理解为何需要进一步核查。

原型的 Python `make_plan` 固定运行三个规则工具，部分条件满足时加第四个；HTML 自带另一份手写评分和演示数据。它没有真实来源接入、模型工具循环、报告期间与口径约束、引用依赖和证据撤回。分数、A–E 可信等级、雷达图及「可以托付」等结论不具备上线依据。特别是「利润为正且经营现金为负」不能证明利润虚增；未查询到记录也不能写成「无涉诉」。队友文件夹没有单独许可证文件，本轮没有直接复制其 Python、HTML、虚构企业数据或视觉资产。

## 本轮吸收的设计

在已有**用户确认采用**的财务材料上，`server/engine.ts` 新增确定性组合核对。只有主体、年度、币种、合并范围通过、原始调整行与现金桥精确闭合时，才形成组合线索：

1. 同公司两期利润增加、经营现金减少，本期应收与存货调整均占用现金。
2. 同期合并利润为正而经营现金净额为负。

每条线索保留触发金额、原件引用、两种尚待检验的解释，并分别给外部付款者与内部接手者下一步材料。页面可点开每项原件，进入对应事项核查；HTML 导出保留相同事实和条件。跨任务对照会指出组合是否仍成立，并提示核对金额和采用材料的变化；未评估组合的旧版报告不会被当作未触发。缺值、冲突、现金桥不闭合或人为撤回关键指标时不生成该组合；「未触发」不等于企业安全。

算法没有采用原型的行业无关阈值、信用／口碑假字段或综合评分。当前真实公开数据仍集中于巨潮 A 股披露；新增信用、司法或舆情通道须先取得可靠来源、适用许可、主体匹配及查询覆盖证明。

## 复核重点

- `tests/engine.test.ts` 用真实已核对年报样本验证组合触发和来源，撤回四种关键指标与制造冲突后结果消失；另用明确的合成变体验证正利润／负经营现金不会被表述成造假。
- `tests/export-context.test.ts` 验证接手视角导出保留组合、来源与下一步材料。
- 具体构建、浏览器及公网版本结果以本轮实际验收记录为准；本文件不把尚未执行的检查写成已通过。
