## 规则、模型与 API

最终整合保留同期报告视图及注册控制更新。`npm run check` 的类型检查、297 项测试、生产构建和格式检查全部通过；固定版本仓库规范检查及只读 GitHub 元数据检查通过。并行原件测试的等待保护从 1.5 秒调整为 5 秒，以容纳增加后的并发 PDF 夹具；原有“持久化失败后不得发出模型请求”断言保持。

新增测试覆盖精确阈值、关键字段缺失及冲突、所选年度合并口径、弱项评级上限、公开字段白名单、数值代入、引用和事件主体、无效输出修复、模型失败回落、真实调用计数及多轮工具协议。模型成功响应使用注入的测试实现，不等于真实 Grok 调用成功。

API 验证覆盖自动研究、账号归属与 CSRF、并发去重、目标与缓存、独立手动限流、同行更新与分析互斥、来源更新撤回旧结论、删除竞态、重启恢复、最后保存失败回滚及过期步骤结束。公开能力接口只报告配置状态、模型名、工具和预算，不包含密钥、服务地址或用户记录。

## 实时工具验证

使用明确标注的固定工具规划测试实现，实际访问公开新闻和官方 PDF；没有向外部 Grok 发送请求，也没有写入本地账号或生产工作区。三轮规划执行四项真实工具动作：读取此前取得的六年财务、检索公司经营新闻、搜索担保公告档案，再读取未缓存的官方公告。

两次外部 HTTP 请求均返回 200；公司名称检查通过一条新闻线索，去重后仍保留 16 条新闻。档案中匹配五条担保公告。实际读取《松原安全：关于公司2026年度对外担保额度预计的公告》，保存前三页内第 1 页的 663 字摘录，文件 SHA256 为 `425118c1a1c669e56c6a2c73b98f2eb1d70273fd1e1e02ac3e7eb724b264981c`。所有七个规划/工具步骤正常结束。

早期真实工具验收发现多轮重复完整资料导致请求超过体积预算；已改为初始单份公开资料、后续轻量研究状态和真实工具结果，保持 1 MB 请求上限。大资料量回归验证第三轮实际进入模型请求，真正超过预算时不发起请求；实际工具流程复验通过。

## 验证边界

截图、实际 JSON、浏览器会话和原始 PDF 位于忽略提交的 `output/playwright/company-assessment/` 与 `work/verification/company-assessment/`。它们未进入仓库，未写入生产账号。

最终工程检查与生产发布使用仓库既有 CI 流程，浏览器和实时来源验收不与模拟模型成功混为一谈。配置状态不证明模型调用成功；引用和数字校验也不证明所有解读语义正确。规则等级尚未按历史违约结果校准，不属于评级机构信用等级。
