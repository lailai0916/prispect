审查日期：2026-10-01（北京时间）。当前阶段是**方案与正在实现的代码静态审查**，不是成品验收。已读取 `docs/plan.md`、`docs/api.md`、`docs/rules.md`、共享合同、核查引擎、材料校验、模型适配器、存储与导出实现，以及当时已经写入的前端片段。源码仍在变化；本文不把尚未写完的组件视为已交付，也不以其暂时缺失判定成品故障。

没有浏览器实测、真人访谈、付费竞品实测或评委评分数据。不编造分数、排名或获奖概率。方案引用的官方要求以规则文档保留的核验范围为限。

## 当前判断

聚焦一个金融信号、使用真实公开材料、解释给非财务用户，符合已读取的 X-Ray 方向。但当前产品仍有变成“现金流图表加通用提示”的明显风险。现金桥是成熟会计方法，已有商业产品提供多源尽调和投研分析；准确计算与漂亮图表只能证明基本完成质量。

更强的可展示差异是：把**一个清楚定义的核查问题**与实际证据连接，允许评委删去、冲突化及补回材料，真实撤回和恢复相应结论；每个待询证问题都说明是哪笔金额、哪个期间、什么证据尚缺。这些功能须在成品中实际跑通。

专业尽调的公开工作方法，不能直接证明“中小企业采购负责人会购买本工具”。目前没有真人需求、付费意愿或节省时间证据。这不要求临时扩大市场调研，但路演必须承认业务假设，并用一个明确合作情境及可复现任务说明价值。

真实账号、持续保存和跨账号隔离属于完整产品的基础质量。它们能证明用户可把核查工作留在自己的空间，不能自动证明金融分析创新、商业需求或公司上线条件已经满足。新增账号页面也不能替代现金证据与询证闭环。

## 必须固定的核查任务

首轮产品与演示应采用明确任务：**核查目标公司某一年度的合并净利润与同年度合并经营现金净额的金额关系，重建可追溯现金桥，并列明解释差额还缺哪些证据。** 公司、年度、合并范围、币种和单位是必需输入。只有取得可比年度的同口径数据，才进一步核查利润与现金的变化趋势。

任务标题是记录名称，不能被包装为已实现任意自然语言说法核查。“利润增长是否兑现为经营现金”只有在利润确实增长且比较期间已核验时才适用；没有比较期时，报告应写本期金额关系。用户新增其他说法前，产品须为该说法定义可检验的条件及所需证据。

完成任务的结果应同时包含：可重算的事实与公式、实际采用的原件定位、尚未证实的原因、针对具体金额和期间的补件问题。只生成比例、瀑布图或一段通用风险提示，不算完成这一核查任务。

## 普通图表产品与本作品的分界

必须把以下路径做成评委能操作的闭环，否则创新叙事缺少对应产品证据：

1. 原始任务得出“金额关系可核算，部分原因仍待核实”，评委能点开合并净利润与 CFO 的原件定位。
2. 移除附注形成独立新任务，保留原任务；界面明确指出撤回了哪些桥步骤、来源和原因解释，而已提供的利润/CFO 事实继续保留。
3. 改成母公司利润与合并 CFO，系统拒绝混用并指出需要什么材料修复，不只是把图变红。
4. 重新提供被移除的合并材料，实际恢复现金桥和对应解释；历史比较能具体展示证据与结论变化。
5. 导出底稿带输入快照、来源、公式与未决问题；用户能继续处理询证问题，刷新后仍存在。

任意新数值的规范导入与实际重算也必须展示一次，避免四个案例被认为四页固定演示。PDF 自动提取能力应按已实测范围描述；需要人工确认的环节应直接呈现。

### 撤证据与补证据的必要演示

以松原 2025 年度为固定演示任务；保留合并净利润与 CFO 的头部证据，撤去现金补充表的调整项证据。这里撤去的是**本次任务允许使用的材料**，不是声称该公司没有披露。整条路径应实际创建、处理和保存任务，而非切换预制页面。

| 阶段           | 必须出现的真实变化                                                                                                                          | 需要保留的验收证据                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 完整材料       | 同口径金额可重算；每个现金桥步骤有允许使用的来源；管理层说法与独立核实分开；具体原因仍保留不确定性                                          | 任务 ID、材料清单、采用的来源 ID、金额、公式、未决问题及输入快照                                                         |
| 撤去调整项     | 另建任务；净利润与 CFO 及其金额关系继续成立；库存、应收、应付和其余已披露调整的桥步骤及相关原因解释撤回；差额不能被重新命名为已解释的“其他” | 新旧任务及明确差异；后端实际采用的证据集合；可选模型可见材料；报告和导出中没有引用被撤去的金额或归因                     |
| 补回明确材料   | 用户明确选择或导入所缺的同口径补充表，系统重新处理，恢复能够由该表支持的桥步骤；仅补回一部分时只恢复相应部分                                | 实际补件材料 ID 与来源、处理记录、恢复项和仍缺项；不能依靠已藏在旧快照里的数据自动补齐                                   |
| 继续询证并导出 | 问题关联具体金额、期间和来源，说明需何种资料区分两种解释；用户更新问题状态后刷新或重新登录仍保留；导出与当前任务一致                        | 问题与发现的一对一关系、保存后状态、实际下载文件；原任务历史不随补件悄然改变，补回财报也不自动证明期后回款或备货原因属实 |

现场应能并排回答三件事：撤去了哪份证据、具体撤回了哪个判断、补回什么材料才恢复了什么。只有“证据不足”徽章或完成状态发生变化，不能证明差异闭环。后台审计快照可保留原材料用于回溯，但本次允许的证据和模型输入必须另受约束。

## 真实账号与完整产品的待验收要求

以下验收须由真实服务端处理和持久化支撑，不能用浏览器本地改用户名或假登录替代。账号能力的完成状态与金融任务的差异证据分别记录。

| 验收对象         | 必须执行的场景                                                                                                                                                        | 通过时才能作出的有限表述                                                |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 首页到私人工作区 | 从公开首页进入真实注册/登录，创建核查、打开来源、保存问题、导出、退出；再次登录后重新打开自己的任务。公开示例与私人导入材料的范围清楚                                 | 指定账号流程与指定核查任务在记录的环境中实际跑通                        |
| 账号生命周期     | 注册失败/重复账号、错误密码、登录、刷新会话、修改资料、改密、退出及过期/失效会话均有实际后端行为；改密后的旧密码和退出后的令牌按已声明策略处理                        | 已验证的账号操作真实可用；未实现的邮件找回不显示为可用                  |
| 用户隔离         | 用受控测试账号 A、B 分别导入不同材料并建任务；检查列表、直接访问已知 ID、复制、改问题、删除、重置、导出和原件访问；未登录请求及 B 对 A 私人数据的请求均应被服务端拒绝 | 已验证指定跨账号读写路径被拒绝；不能扩大成“全部安全漏洞已排除”          |
| 数据持久化       | 更新问题并保存；刷新、退出重登、服务重启后核对账户归属、任务快照、材料和问题状态；重置仅影响当前账号                                                                  | 在记录的重启和恢复场景中，指定数据保持一致                              |
| 接口与身份保护   | 核对密码和会话存储形式、Cookie 属性、实际登录限流、CSRF 防护、错误响应；部署环境核对 HTTPS 与安全 Cookie。拒绝场景需有请求/响应或适当测试结果                         | 记录中列出的保护措施经过对应检查；不是完整安全审计结论                  |
| 真实处理         | 导入一个非预置的新规范输入并实际重算；测试缺失、口径冲突及无效文件；PDF 提取不能确认时停在确认或不足状态；规则分析与实际模型调用状态准确显示                          | 已测格式与样本可用；不宣传任意公司、任意 PDF 或已执行并未配置的模型推理 |
| 部署可访问性     | 在实际部署地址及新浏览器会话执行首页→账号→导入→固定任务→撤证据→补证据→来源→导出，记录环境、日期与限制；直接路由、失败恢复和原件访问也需核对                           | 在指定部署环境可使用这条功能链路；本机成功不能代替公网验收              |

“略微修改可公司上线”应由可重复部署、账户与数据归属、实际输入处理、故障与恢复步骤共同支撑。单机多账号的真实可用性不等于多节点扩展、运营监控或全部商业数据权限已验收。缺少实际域名/TLS、备份恢复证据、隐私说明或商用材料授权时，应在交付边界中列出，不能以账号页存在就称生产上线条件齐备。

经营现金净额是经营流入与流出的净额，不是销售回款率。“利润没有等额体现为经营现金”可以作为白话入口，但不能进一步将差额全部解释成未收回销售款。

## 商业价值应怎样展示

建议选定一个明确的假设情境，例如采购负责人准备与上市供应商开始一段交付周期较长的合作，需要先准备财务询证问题。演示应让观众看见：过去需要在长报告里定位两个不同利润口径和现金补充表，现在能按来源定位、同口径重算、识别材料缺口，再生成具体问题。

这是任务价值的展示，仍不是采购市场需求、付款决策效果或付费意愿的实证。成品验收可记录完成指定核查任务的步骤和成功情况；没有真人对照时，不制作节省时间、用户满意度或市场规模数字。

功能优先级应围绕现金证据与询证闭环。再增加库存图、行业榜单、风险总分、全网新闻页面，不会解决当前差异证据薄弱的问题，还会扩大数据和授权边界。

## 演示薄弱点与准备

- 先给一句固定、可检验的问题，再进图表；否则非金融评委不容易理解为什么这一比例重要。
- 首页、账号和设置页用于让核心任务能够被真正开始、保存和继续；正式金融演示不宜把注册表单的完整度作为主要创新亮点。
- 现金桥六项存在数值尺度差异；需能在几十秒内看懂净利润、占款、其余调整与 CFO，全部精确金额保持可查。
- 原件如果只有外链，现场网络失败会破坏“可追溯”叙事。本机原件定位必须确认能打开正确页，并保留独立离线展示。
- 缺失案例不能只有徽章变化，应明确展示被撤回的具体归因和还成立的事实。
- 母公司冲突案例应让观众看见真实原文口径，不能靠预置数据故意改标签而声称已经解析原报告。
- 中英文界面不能只翻译导航；报告标题、解释、错误和阶段文字也需核验。中文原文可保留其来源语言。
- 三位成员尚需理解合并与归母差别、净额与收款率差别、缺失为何不能填零，以及独立核验与公司说法的差别。开发工具生成内容不能冒充成员已经独立作出的判断。
