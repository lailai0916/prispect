## 不可直接迁移的数据链路

1. **失败被改写为无结果。** `finance/seam.js` 在每次分发中尝试不同 Provider，除非法输入外继续降级；全部失败后，部分方法仍抛 `NOT_FOUND`。东方财富 Provider 自身还会将请求错误改为空数组或 `null`。超时、限流、不可用和真实空结果由此混淆，不能用来表示企业不存在或没有相关记录。
2. **各字段可能来自不同来源。** 企业、财务、公告和覆盖状态各自分发，缓存没有绑定完整查询版本及来源组合；演示 Provider 又优先于真实快照。不能把这些结果自动合成一个主体、期间和证据口径已确认的报告。
3. **旧债务链路将缺失填零。** `fetch_financials.py:185–209` 使用 `or 0` 合计短期借款和一年内到期非流动负债；`assets/app.js:59–61` 继续使用缺失默认零，并可能输出“无短期有息负债”。新版核心虽然改为缺分项返回未知，旧快照和旧页面仍保留另一套口径。受限资金未知时，货币资金余额也不能当作可动用现金。
4. **归母利润与合并现金混算。** 采集脚本区分 `PARENT_NETPROFIT` 与 `NETPROFIT`，但旧页面和预缓存现金比率使用前者作分母。新版 `financial-core.js` 已改用 `netProfitAll`，这不能追溯修复旧比率和静态叙述。Prispect 继续要求合并净利润，未将归母字段自动映射为合并利润。
5. **数量与标签不证明覆盖。** 五年记录、公告命中数量、`available` 或 `full` 只说明该快照字段的情况，不能证明完整年度表、年报审计意见、司法信用、工商或舆情已经查询并核实。年报检索 URL 是定位入口，不是已定位的原文依据。
6. **阈值与叙述不替代调查。** 旧版按现金比率、负债率等通用阈值分色，部分静态叙述将金额关系归因为回款节奏等原因。没有行业校准、原件依赖和证据撤回机制时，不应迁入企业评级、因果结论或可靠性保证。

本批没有复制附件代码或视觉资产，也没有引入虚构案例、五年快照、静态企业推断、旧评分 / 分色阈值或未接通的数据服务。

## 值得借鉴的设计

- 双视角共享事实与来源，通过重点、操作顺序和材料请求区分外部交款者与内部接手者。
- 让每个调查问题包含触发理由、所需材料和下一步联系建议，避免用户读完报告仍不知道如何行动。
- 以逐项缺口、公式与原文下钻表达不确定性；来源通道状态、数据完整性和原件采用状态分别记录，不能合成笼统“已接入”。
- 导出前预览具体内容，再由用户保存同一份文件；体验测试观察用户能否说清金额关系、打开依据和识别未知。

首批借鉴了数据来源抽象与用户理解测试的设计，没有另建附件的 Provider SDK。随后按用户要求，另行实现并核对了匿名东方财富网页字段通道与图表，详见下文；没有宣称已完成用户价值研究。

## 本批已写入 Prispect 的功能

### 双视角重点与下一步

[Report.tsx](../src/pages/Report.tsx) 在报告顶部增加用途切换与下一项材料请求。外部视角先核对签约主体、收款安排、承诺条款与退出条件；接手视角先核对当前可用资金和到期付款。两者共享报告事实，分别进入已有付款 / 接手事项工作区。

用途切换调用 [ReviewContext.tsx](../src/ReviewContext.tsx) 的上下文保存流程，包含当前编辑中的场景备注。顶部没有把年度现金净额填成当前余额，也没有据历史利润判断本次付款安全。

### 询证排序、角色建议和 Markdown 清单

[reviewChecklist.ts](../src/reviewChecklist.ts) 同时供页面与 Markdown 导出使用。未完成的材料 / 口径补充问题优先；有合法已保存触发金额的问题按历史现金影响绝对额排序，使用整数分；没有有效触发金额的询证保留相对顺序；已记录完成的项目置后。金额只解释跟进先后，不构成风险或信用评级；完成状态只表示跟进记录。

角色建议按外部 / 接手用途及询证内容指向财务、客户结算或订单库存负责人，并明确实际联系人待确认。清单保留用途、年度、保存更新时间、状态、排序理由、所需材料、触发金额、材料标识、PDF 页码、原文、来源 URL 与已有哈希。非法金额保留原值但不用于排序；缺件、冲突与历史边界明确保留。旧报告没有触发金额或组合核查状态时不从指标补算。

### 导出预览

[ExportPreview.tsx](../src/ExportPreview.tsx) 提供 HTML 报告、JSON 数据和 Markdown 询证清单的预览及保存。财报 HTML / JSON 经已有账号隔离的导出接口读取；保存使用已预览的同一份原始内容。服务端对预期保存时间不一致的请求返回明确更新提示，避免静默导出另一版本。私人事项 JSON 使用已读取的选定历史版本快照，预览与保存均绑定该版本。

HTML 在受限 iframe 中预览，阻止脚本、表单和外部资源；文本预览不会被当作 HTML 执行。预览存在载入、失败、重试与报告变化状态。这是本批实现的交互，不等于所有浏览器和公网部署已完成验收。

### 有来源的两期变动公式

[server/engine.ts](../server/engine.ts) 为合并净利润和经营现金增加已保存变动额：**本年金额 − 上年金额**。仅采用同主体、相邻年度、人民币合并年度观测，按分计算，并保留两期来源；常规同比继续要求上年基数为正。前期零值或负值可以保留金额变化，百分比保持不适用。

当前材料或原始分组 / 现金桥存在冲突时，变动额与同比暂停；仅缺现金桥调整资料时，已确认的两期利润和经营现金仍可比较。页面展开已保存两期金额、减法代入、同比公式和各期引用；旧报告缺少变动额字段时显示未保存，不在客户端重新计算。模型的冲突、范围和证据采用门控没有被这些字段绕过。

## 后续吸收：匿名财务通道与交互图表

附件 `_构建脚本/fetch_financials.py` 使用的东方财富网页接口可以在没有账号、Cookie 或商业 API Key 的情况下请求。已直接核对实际响应及[东方财富 F10 页面](https://emweb.securities.eastmoney.com/pc_hsf10/pages/index.html?type=web&code=SH600519)加载的字段映射：`NETPROFIT` 是净利润，`PARENT_NETPROFIT` 是归母净利润，二者不可互换；接口表名前缀 `G` 本身不能证明报表已经与合并年报原件核对。

Prispect 新增 [company-market.ts](../server/company-market.ts)，在既有 Agent 的请求预算和并发限制内独立读取利润、现金流与资产负债表。该节点每次执行最多三次匿名 GET、每张表十秒和两 MB、最多六个年度；中断恢复仍受整个查询的累计请求预算限制；证券代码 / 市场、机构代码、行业、人民币币种及年度记录均需核对。只处理通用行业字段，银行等不同表结构保留不支持状态；某张表失败不阻塞官方年报原件检索，也不把失败伪装成没有风险。

原始数字 token 先保留为字符串，按整数分规范化，避免先经过浮点数再声称精确。空值、异常精度、重复年度冲突保持未知；两张表净利润冲突时暂停该年度利润 / 经营现金对照。短期借款与一年内到期非流动负债只有都已知时才求和；该合计不是全部到期义务，货币资金也不是当前可用余额。来源保留实际请求 URL、取数时间、公告 / 更新时间和原始响应 SHA256；哈希用于辨识响应，不能证明字段已与财报原件核对。

[CompanyFinancialTrends.tsx](../src/CompanyFinancialTrends.tsx) 提供三组图表：利润与经营现金、收入与利润、货币资金与两项负债。收入和利润分别使用自己的刻度并对齐年度，避免利润被收入尺度淹没；鼠标和键盘可选年度 / 字段，展开精确金额及对应来源，缺年保留横轴空档，零值、负数和缺值分别呈现。网页字段与同主体、同年度、通过口径检查的原件候选值独立比较，显示一致、不同或未核对；不自动导入为正式材料。已有财报报告的两期图也增加逐年度、逐指标原文定位。

新查询采用独立的图版本；旧 checkpoint 恢复继续使用旧拓扑，旧查询不追加网页字段请求或客户端补算。数据使用说明同步到隐私政策与使用文档，不要求用户额外注册东方财富账号或提供密钥。
