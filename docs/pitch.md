## 五分钟讲稿

建议一位主讲、一位操作、一位负责原件及追问。角色是排练建议，不代表已经分配或已经完成贡献。以下时间包含短暂停顿和操作；首次实际排练应计时调整。

### 0:00–0:40：先给一组真实反差

“我们做的是照见 CashLens。它从一个具体问题开始：一家公司的利润，有多少体现为同年度经营现金？

“松原安全 2025 年度合并净利润约 3.66 亿元，经营现金净额约 2619.71 万元，两者比例约 7.15%。数据来自正式年报。这不证明公司造假，也不是说只有 7.15% 的销售款收回来了。它提示我们：需要沿着现金补充表继续核查，不能只看利润。”

操作：显示公司、年度、合并口径、币种及原件来源。金额展示可取合理小数，精确值必须可查。

### 0:40–1:15：把用户任务讲清楚

“我们的目标用户假设是采购与经营负责人。比如，准备与一家上市供应商开始长周期合作，需要先把财务问题问清楚。

“照见固定完成一项任务：比较同年度合并利润与经营现金，重建有出处的现金桥，再列出原因还缺什么证据。用户可以把底稿交给财务或合作方，索取明确的材料。专业尽调确实会检查现金配比、账龄和期后回款，但我们还没有采购用户访谈或付费验证。今天展示的是这个任务怎样被完成。”

操作：进入该年度核查，指出标题是底稿名称，核查目标和必需口径另有明确说明。

### 1:15–2:05：从比例走到原件和问题

“这里从合并净利润出发，经过存货、经营性应收、经营性应付和其余已披露调整，到达经营现金净额。每项都能返回材料、页码和短摘录。海康威视的样本还用于检查另一个常见问题：归母净利润不能直接与合并现金流混算。

“桥闭合，说明这些金额在算术上能够核对。经营原因仍需材料支持。应收调整为负，可能涉及结算时点、票据及经营规模变化，也可能需要排查回款压力。我们把公司解释与尚待验证的原因分开，并提出针对具体年度、金额和资料的询证问题。”

操作：打开一项调整的原件定位及对应问题。其余调整须能展示原表已列示行的分组依据，不能只把残差命名为其他。

### 2:05–3:15：让评委看见证据改变结论

“接下来只保留利润和经营现金的头部材料，撤去本次允许使用的现金补充表。原任务保留，再建立新的核查。

“两项头部事实和金额差距还成立；失去出处的桥步骤和相关归因撤回。问题单说明需要补哪份表，以及期间和口径。

“明确补回这份同口径材料后，重新处理，能够由材料支持的桥步骤恢复。补回财报并不会自动证明客户已经回款，期后回款等问题仍然未决。我们也准备了母公司利润混用合并现金流的输入，系统应阻止这次计算并指出修复办法。”

操作：在完整报告调整本次采用的证据，排除调整项并另建任务；随后取消排除、恢复证据并重新核查。比较页展示具体撤回和恢复项，口径冲突可在答辩时打开。前一版这条路径已实测；实际按钮名和新录制画面在改版验收后锁定，不用旧截图代替。

### 3:15–4:05：真实产品怎样继续工作

“这项核查需要保存和继续，所以我们把它做成有账号与私人工作区的产品。用户可以导入支持的规范材料、保存任务、更新问题，再输出当前底稿。来源、公式、输入快照和未决问题随底稿保存。

“金额核算、口径检查和证据筛选由确定性处理完成。每个新任务默认规则分析；用户主动选择后，可以把本次允许的观察和短摘录交给已配置的第三方服务解释。开发工具的 AI 参与与网站运行时的调用，我们分别说明。”

操作：保存一个问题状态，重新打开任务，实际下载底稿。指定测试任务的状态刷新与重登保存已实测；跨账号隔离只按对应受控测试结果说明，避免在舞台上展示真实用户数据或密码。

### 4:05–5:00：说明差异和实际边界

“企业尽调报告和现金桥都有成熟方法与商业供给。我们选择展示的差异是：把一个明确核查任务、可回到原件的金额、证据变动后的结论变化，以及继续询证的动作连接起来。账号是完整产品的基础质量，金融价值要由这条任务链证明。

“当前样本是两家公司的 2025 年报及 2024 年比较列，不是实时公司评分，也不作违约预测或投资建议。目标用户、付费意愿和商用数据权限仍需验证。开发中 AI 工具参与了研究、方案、代码与文稿；三位成员需要复核这些判断，具体人类贡献按真实记录说明。

“照见输出带来源、计算和待询证问题的底稿，供用户继续核对材料。”

操作：显示未决问题、方法范围及数据/工具说明，结束前保持一个可操作报告页面供评委继续检查。

## 新版界面与展示材料

用户要求使用系统字体、石墨蓝、中性色和任务导向的简洁排版。页面不再靠英文大写标语、反问、对偶句或“真实处理”自证；演示直接显示公司、年度、金额、来源、调整操作和问题状态。这个方向正在实现，尚无新版浏览器通过结论。

旧 12 页草稿的逐页记录与哈希保留在 [judge-review.md](judge-review.md)，其后的候选改稿因本轮风格变更停止验收。最终 PDF/视频需重新使用通过检查的实际界面，放大原文、具体问题与撤回/恢复内容。五分钟主线仍是数值反差 → 用户任务 → 原件与询证 → 调整证据 → 保存与导出；新页序和按钮名在改版验收、真人计时后确定。

## 尖锐问答

| 追问                                     | 可据事实回答                                                                                                                                                                                                                       |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7.15% 是不是说明剩下的钱收不回来？       | 不是。这是年度经营现金净额除以合并净利润，不是销售回款率。现金净额还包含经营流出及多种调整；坏账需要账龄、期后回款等证据。                                                                                                         |
| 你们到底发现了公司什么风险？             | 找到需要继续核查的现金与利润差距及材料请求，未独立证明坏账、滞销、造假或违约。松原年报还披露票据结算与扩产解释，不能忽略。                                                                                                         |
| 为什么海康的利润与你查到的归母不同？     | 使用的是合并净利润，包含少数股东损益；合并 CFO 需与同范围利润核对。海康年报另有母公司现金桥，不能混入。来源见研究文档的 PDF 第 229 页。                                                                                            |
| “其余调整”是不是你们为了凑平？           | 已核验样本将原表其余列示行独立求和，再与残差比对。未知输入若没有这些行，只能叫未归因差额，不能宣称已经解释。                                                                                                                       |
| 两种可能解释是不是普通大模型都能编？     | 通用文字很容易生成。验收关注的是每种解释绑定哪项真实金额、缺什么资料、证据删除后是否撤回，以及补件后哪些判断恢复；没有这条闭环就缺乏产品差异。                                                                                     |
| 删证据后，你们是不是还从原材料里偷偷读？ | 审计快照保留原件供回溯，本次允许证据另受限制。本机撤调整任务保留两项金额，桥和相关归因撤回；比较及 JSON 可复核。可选模型过滤要看对应测试，不能由徽章或审计快照本身推出。                                                           |
| 既然模型可选，为什么叫 AI 项目？         | 模型承担受约束解释，数值核算和证据检查由规则完成。新任务默认不外发，主动选择才请求第三方 TokenFlux。主线程已记录公开财报真实调用成功，mock 则只验证适配路径；两者分别披露。                                                        |
| 真调用是什么模型？                       | 第三方 TokenFlux（tokenflux.dev）返回的服务标识是 gpt-6.1-sol。主线程记录一次公开财报调用完成 23,238 ms，新提示词的一次 UI explain→save 流程为 43,720 ms；第三方延迟浮动，两者不是同一计时范围。这不是官方直连或独立上游型号验证。 |
| 账号系统为什么算创新？                   | 账号主要解决私人材料、任务保存和继续工作，是实现质量。创新叙事仍应由核查、证据变动、结论撤回与继续询证的实际工作流承担。                                                                                                           |
| 测试是否证明产品全部安全可靠？           | 前一版 21 项本机单元/API 测试与 37 项独立公网 API 断言分别证明记录中的场景，另有指定浏览器路径。它们不替代新版 UI 验收或完整安全审计，不把不同范围的测试简单相加成全面保证。                                                       |
| 谁真的需要它，谁愿意付钱？               | 中小企业采购与经营负责人是目标用户假设；未开展真人访谈或付费验证。专业机构的公开方法证明核查内容有实际使用，但不能替代对该目标用户的验证。                                                                                         |
| 相比 Wind、企查查有什么领先？            | 这些厂商已有多源尽调、评分及报告能力，我们未付费实测，不能说其缺少本产品功能。我们展示的是自己选择并实现的窄任务工作流，不作全面领先或首创声明。                                                                                   |
| 公开财报能直接拿来商业上线吗？           | 公开可读不等于无限商用或再分发许可。本轮为非商业参赛研究，保留出处与权利；完整 PDF 不在代码许可证下重新授权。商业上线须再核数据权限，用户上传非公开资料也须有授权。                                                                |
| xuejun.cc 已经可以供企业使用了吗？       | HTTPS 网站已上线，指定账号、规则核查、原件和导出路径及 37 项 API 断言有独立记录。当前全站简洁风格改版仍待验收；实际运营的数据授权、容量和持续维护需另核，指定成功路径不是企业运营条件全部齐备的证明。                              |
| 三位成员分别做了什么？                   | 只按真实记录回答。AI 工具参与了研究、方案、代码、核验辅助与文稿；成员的复核、修改、测试、解释与现场操作需实际完成后再归入个人贡献。不能把生成内容直接称为成员独立完成。                                                            |
| 私有仓库评委怎么看？                     | 按主办方认可方式确认评委账号及访问范围，由团队授权并实测仓库、README、运行说明与必要附件。也可依确认规则准备离线源码包；没有授予并验证权限前，不称已可访问。                                                                       |
| 现场网络或功能失败怎么办？               | 直接说明当前失败，展示标注为录制的已验收操作视频及有出处的离线材料。若某一功能从未跑通，就保留未完成状态；不能用录制内容冒充当前实时操作。                                                                                         |
